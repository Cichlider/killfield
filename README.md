# killfield

**[▶ 在线试玩](https://cichlider.github.io/killfield/)**

浏览器里的迷宫坦克对战，配一个搜索型 AI 对手。
纯 ES 模块，零依赖、零构建步骤，克隆下来起个 HTTP 服务就能跑。

---

## 原理

AI 每帧要回答两个问题：**往哪走**，**朝哪开火**。

这张地图里墙很多，直射的机会很少，大部分击杀得靠子弹反弹。
所以常规的「我从这里开枪能不能打中」很难算——要枚举所有角度、逐条模拟反弹。

这里把问题反过来：

> 不问「我能不能打中他」，而问「**子弹可能是从哪些格子飞过来的**」。

具体做法是从敌人所在的格子向外发射一圈反向射线，让它们按墙面反弹传播。
射线经过的格子，就是能打到敌人的格子。统计下来得到一张覆盖全图的密度场——
颜色越深的地方，可行的射击角度越多。

这张场同时解决了那两个问题：

- **往哪走** —— 朝密度更高的格子移动
- **朝哪开火** —— 当前格子里命中角度最密集的那个方向

在此基础上，每次重规划会比较 18 条轨迹：9 条持续移动方案，以及 9 条
「首帧静止开火、次帧起采用不同移动」的方案。每条轨迹都在沙盒里前推 36 帧，
按「是否更接近好射位 / 炮口是否更对准 / 会不会吃子弹 / 开火后能否安全续走」
打分，选最优的首帧动作执行。开火不再无条件覆盖移动与躲避，而是在同一评分中竞争。

游玩页右侧提供一块**实时参数面板**，可以直接调整导航、追猎、开火纪律与风险权重。
修改从下一次规划开始生效，并自动保存在当前浏览器；“恢复默认值”可随时回到仓库中经过
基准测试的配置。观看 AI 对战时不需要停局或重新加载页面，适合快速观察 reward/score
改动是否让局部最优行为朝预期方向变化。

## 运行

ES 模块不能从 `file://` 加载，起个本地服务即可：

```bash
python3 -m http.server 8000
```

## 结构

```
src/game.js          引擎：坦克、子弹、回合状态机（固定 25 FPS）
src/maze.js          迷宫生成、连通性、距离场、墙体索引
src/laika.js         对照用的脚本 AI 对手
src/killfield/       AI：密度场、候选动作搜索、打分、风险估计
test/                单元测试与行为基准
```

实现细节见 [DESIGN.md](DESIGN.md)。
