# Killfield · `rl` 分支

在 Tank Trouble 风格的迷宫坦克对战里，用 PPO 从零训练一个能自己找路、追人、开枪的智能体。

引擎、物理、弹道用 Rust 写；训练器和网页 Viewer 链接**同一份 crate**，所以网页上看到的
就是训练时跑的那套物理，没有第二套 JS 实现。`main` 分支上有一个零训练的实时 MPC 规划器，
对固定脚本对手 Laika 胜率 **88.7%**（2000 局）——它是这条 RL 线的性能上界参照，不是本分支的内容。

```sh
python3 -m venv .venv && .venv/bin/pip install -r training/requirements.txt
bash viewer/serve.sh          # http://127.0.0.1:8000/
```

## 1. O / A / R

### O：观测 —— schema 10，1182 维

原则是**只给「关于世界的事实」，不给「关于决策的答案」**。所有方向量都转到以自身车头为
正前方的坐标系。

| 组 | 维度 | 内容 |
|---|---:|---|
| 全局迷宫 | 840 | `12×10` 格 × 7 个二值通道：格有效、上/右/下/左墙、我在此格、敌在此格 |
| 当前导航 | 5 | 当前 waypoint 的四方向 one-hot + 剩余路径格数 |
| 自身坦克 | 9 | 位置、朝向 `cos/sin`、空闲弹槽、存活、能否开火、是否撞墙、是否贴墙滑行 |
| 对手坦克 | 6 | 自车坐标系下的相对位置、相对朝向、空闲弹槽、存活 |
| 全部子弹 | ≤60 | 最多 10 发 × 6 维：相对位置、相对速度、归属、是否已反弹 |
| 回合阶段 | 3 | 交战中 / 已死但残弹结算中 / 冻结重置 |
| 时间 | 1 | 已用帧数 `/750`，裁剪到 `[0,1]` |
| 上一次动作 | 258 | `Discrete(258)` 独热 |

**明确不给**：地图种子与 RNG、对手按键与未来动作、子弹精确寿命与未来轨迹、精确视线判定、
瞄准误差、击杀场值、风险分数、最佳射位与射角、MPC 对候选动作的评分。

子弹这 10 行必须过共享编码器 + 带掩码池化，它们的存储顺序不是策略特征。

### A：动作 —— `Discrete(258)`

```
action = movement * 2 + fire

movement 0..127 : 128 个绝对世界方向（每档 2.8125°），车头瞬转后前进
movement 128    : 原地不动
fire 0/1        : 本帧是否扣扳机
→ 256 = STOP，257 = 原地开火
```

- **开火与移动正交**，扳机是独立一位，可以边走边打；
- **没有倒车挡**，身后的目标靠转头到位；
- 方向**瞬间对齐、无转速限制**；若瞬转会让车体进墙则拒绝转向、保持原朝向；
- 25 Hz，每引擎帧决策一次；每局清空记忆。

网页给人用的摇杆是另一条路径（360 方向 + 270°/90° 前进/后退分区），与 PPO 动作空间无关。

### R：**还没有定下来**

O 和 A 已经冻结，R 没有。四轮迭代每一轮都推翻了上一轮的奖励，而且每一轮推翻的理由都成立
（见第 2 节）。与其把当前这版说成设计，不如说清楚我卡在哪里——这些问题在我看来**几乎全部
是 credit assignment 问题**：这个游戏里「一件好事发生了」和「哪个动作该为它拿分」之间，隔着
好几层不平凡的东西。

#### 1. 距离变小了，是谁干的？

`BFS(我, 敌)` 会因为两边移动而变化。直接拿它的差分当奖励，等于把对方走过来的距离也算成我的
功劳。实测这个污染在真实迷宫上占 **85%**——模型净远离 16 格，目标自己走近 89 格，旧塑形照样
发钱；房间图上占 **50%**，因为目标沿固定路线巡游，蹲在必经点就能白拿。

现在的处理是**反事实归因**：把目标冻结在上一帧的位置，只计我方位移造成的那部分。

```
own_delta = dist(上一帧我的格 → 上一帧目标的格)
          − dist(这一帧我的格 → 上一帧目标的格)
```

这条我认为是对的，也确实起效了（房间图 minBFS 从 5.0 做到 3.0，存活 31→207 帧）。但它只解决了
**空间上**的归属，没解决下面的时间归属。

#### 2. 死因可能发生在十秒之前

子弹寿命 **250 帧（10 秒）**、可以无限次反弹、并且对开火者本人同样致命。所以「我方死亡 −300」
这个终局，真正的责任动作往往是**几百帧之前那一次开火**，而惩罚落在当时恰好在执行的那个动作上。
v3 的房间图上模型稳定走到贴脸然后 100% 自杀——它到底有没有可能学到"刚才那一枪不该开"？
`gamma=0.9975` 在 250 帧上衰减到 `0.53`，信号是能传回去，但中间隔着上百个与死因无关的动作。

这个仓库里其实已经有一套**追溯归因**的设计（`retroactive_allocations`）：击杀奖励的 30% 分给
击杀前 12 秒内真正提高了进攻势能的动作，用 `sqrt(H_i−H_0) − sqrt(H_{i−1}−H_0)` 加权，只有创下
新高的动作拿分。它是为击杀质量写的，还没有用在死因上。**该不该把同样的机制用于负向终局？**

#### 3. 稠密塑形和稀疏终局的量级对撞

塑形是每帧结算、永不封顶的；终局是一次性的。谁的量级大，谁就实际决定策略。第一版塑形整局累计
约 `−187`，而撞墙死只扣 `−10`，于是「第 2 帧去死」严格优于「活着探索」，PPO 找到了这个答案，
回合长度从 8.9 帧塌到 2.2 帧。改成 `−300` 之后立刻单调爬到 114 帧。

**盈亏平衡点是可以算的**（这里是 `−200`），但"算出临界值再留余量"更像救火而不是设计。稠密项和
稀疏项之间有没有更原则性的定标方式？

#### 4. 塑形的符号，和梯度在轨迹上的分布

`−exp(BFS当前 − BFS初始)` 恒 ≤ 0：靠近只能让失血变慢，**永远赚不到钱**，唯一的正数 `+50` 又
要求先学会全套本事。而且它 95% 的梯度挤在最初 3 格，走到 12 格之后信号几乎为零——minBFS 就
死死卡在那里。对比本仓库唯一冷启动成功的 walking-v6，它有 `+5` 路径进度和 `+10` 到达，**都是正的**。

换成线性的 `±1/格` 之后逼近行为立刻出现。但线性也只是"看起来均匀"，并没有理由说明它就是对的。

#### 5. 开火是边沿触发的，动作和后果不是一一对应

`fire` 是每帧一位，但引擎里开火是**上升沿**触发：一直按住只打出一发。所以一串 `fire=1` 里只有
第一帧真的做了事，其余帧的 `fire=1` 是 no-op——却照样进入观测的"上一次动作"、照样被记账。
v3 的 argmax 就退化成「边走边一直按住」，全局只有一发子弹，而那一发就是它的死因。
**这算动作空间设计问题，还是 credit assignment 问题？** 我倾向于两者是同一个问题的两面。

#### 6. 目标在动，同一个动作的价值取决于对方接下来怎么走

追一个随机游走的目标时，"往这边走"是好是坏，一部分取决于目标下一步的选择——那是策略观测不到、
也无法控制的随机量。这部分方差直接进了优势估计。反事实归因（第 1 条）去掉了**已经发生**的那部分，
但去不掉**未来**那部分。

#### 7. 混合地图会把 credit 劈开

v2/v3 用 50/50 混合训练，本意是拿简单图当锚点。但观测里带完整迷宫布局，**策略能分辨自己在哪张图**，
于是学出了两套各自退化的策略：房间图一直扣扳机贴脸自杀，真实迷宫干脆不开枪只剩撞墙。共享的不是
能力，而是参数。

---

**当前跑着的这一版（临时，不是结论）**：地图 50/50 混合（`6×3` 走廊接 `2×2` 房间，出生 BFS 7；
真实迷宫 `5×10`，出生 BFS 18），目标武器锁死、从不开火，两张图规则一致。每帧按优先级结算：

| 顺序 | 条件 | 奖励 | 终止 |
|---:|---|---:|---|
| ① | 我方死亡（唯一死法是自己的反弹弹） | −300 | 是 |
| ② | 目标死亡 | +50 | 是 |
| ③ | 撞墙 / 贴墙滑行 / 本帧无位移 | −300 | 是 |
| ④ | 以上都没有 → 主动靠近 | ±1 × 自己缩短的格数 | 否 |

选中 STOP 在推进物理之前就判 `−300`；开火完全合法；750 帧 truncation 给 0，追上不结束回合。
①②③ 的顺序是刻意的——尸体不会位移，先判位移会把反弹弹自杀记成「无位移失败」。

## 3. 待解决 / 想请教的问题

**1. 这套 O/A/R 本身合理吗？**
观测上我守的规矩是「给事实、不给答案」，所以把精确 LOS、瞄准误差、击杀场、风险分、MPC 的候选
评分全部排除在外。但 v3 的结果显示它能走到贴脸却不会开枪——这到底是**观测里缺了判断一枪好坏
所需的事实**（比如"沿当前炮口方向第一个障碍是墙还是人、距离多远"），还是**奖励没给引导**？
这两者的边界在哪里？`Discrete(258)` 把开火拆成独立一位、并取消倒车挡，是不是过度简化了？

**2. MPC 能不能行为蒸馏？我的结论是不能，但想知道根因。**
这条路在历史实验里反复失败：老师 96–100%，学生 64–88%。具体证据是——MPC 的 18 个候选**中位
有 14 个并列**，完美预测器的 top-1 上限只有 **11.9%**，所以 argmax 标签本身就不可教
（P19 argmax BC 蒸馏 30.8%）；评分回归在原观测下只有 14%，诊断是「观测全是动作无关特征，
标签问的却是往哪躲能活」；最狠的一条是**特权老师压不进网络**——能看到对手真实 RNG 和内部
目标栈的 exact-state teacher 有 100% 胜率，蒸馏后 action agreement 卡在 **22.5%**，
observation-only 的安全分类器 held-out **0%**。

唯一一次跳变是 P21b：**同一个方法、只把观测换成 408 维全知**，从 14% 涨到 **62.2%**。
这似乎指向「差距来自学生观测里不存在老师用来排序动作的信息」。但如果补足那些信息就等于把
搜索的答案喂进去，蒸馏还剩多少意义？**这是观测问题、标签语义问题，还是搜索本身不可压缩？**

**3. 观测定下来之后，这类游戏的 reward shaping 该按什么顺序做？为什么？**
我这四轮是「发现问题 → 补一项 → 再发现下一个问题」，事后看更像在打地鼠：修好送死最优，
撞上塑形无正梯度；修好正梯度，撞上信号被对方污染；修好污染，撞上不会开火。
有没有一个更有原则的推进顺序（比如先终局、再势函数、再行为质量），以及每一步该用什么判据
确认「这一层已经站住了、可以加下一层」？

**4. 能不能一张图专练寻路/瞄准/击杀，另一张图专练躲子弹，再把两种能力在训练上结合？**
这正是我第 v2 轮试过的 50/50 混合，结果是**反效果**：观测里带完整迷宫布局，策略能分辨自己在
哪张图，于是学出了两套各自退化的策略——房间图一直扣扳机贴脸自杀，真实迷宫干脆不开枪只剩撞墙。
混合没有正则化，而是把策略**劈成了两半**。

那么：能力拆分训练在这类任务上到底可不可行？如果可行，是该用**课程顺序**（先 A 后 B，热启动）
而不是**同批混合**？怎么防止后一个阶段把前一个阶段的能力洗掉（本仓库有过「已收敛策略的单点
矫正会破坏自平衡」的教训，五次独立验证）？还是说更该走**共享表征 + 分头**、或者干脆多任务
但把任务 id 从观测里去掉？
