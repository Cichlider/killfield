# Killfield · `rl` 分支

在 Tank Trouble 风格的迷宫坦克对战里，用 PPO 从零训练一个能自己找路、追人、开枪的智能体。

引擎、物理、弹道用 Rust 写；训练器和网页 Viewer 链接**同一份 crate**，所以网页上看到的
就是训练时跑的那套物理，没有第二套 JS 实现。`main` 分支上有一个零训练的实时 MPC 规划器，
对固定脚本对手 Laika 胜率 **90.2%**（500 局，512 rays）——它是这条 RL 线的性能上界参照。

```sh
python3 -m venv .venv && .venv/bin/pip install -r training/requirements.txt
bash viewer/serve.sh          # http://127.0.0.1:8000/
```

接手请先读 [`docs/HANDOFF.md`](docs/HANDOFF.md)。

## 1. O / A / R

当前课程是 **duel-v1**：真实对战，每局随机迷宫，双方都能开火，30 秒未分胜负判平。
完整定义见 [`docs/DESIGN.md`](docs/DESIGN.md)。

### O：观测 —— schema 20，1010 维

原则是**只给「关于世界的事实」，不给「关于决策的答案」**。所有方向量转到以自身车头为
正前方的坐标系，全通道有界在 `[-1, 1]`。

| 组 | 维度 | 内容 |
|---|---:|---|
| 迷宫栅格 | 840 | 补齐到 `12×10`，每格 7 个二值通道：格有效、上/右/下/左墙、我在此格、敌在此格 |
| 墙射线 | 16 | 绕车体 16 向到第一堵墙，上限 4 格 |
| 自身 | 12 | 位置、朝向、速度、角速度、弹槽、能否开火、存活、撞墙、贴墙滑行 |
| 对手 | 12 | 同上，全部转到我车坐标系，含**相对朝向** |
| 导航 | 10 | BFS 格数、梯度四方向 one-hot、直线距离、方位、双方所在格的死胡同惩罚 |
| 瞄准辅助 | 5 + 5 | 当前炮口的完整反弹轨迹模拟，**双方各一份** |
| 全部子弹 | 100 | 10 发 × 10 维：相对位姿速度、归属、已反弹、**剩余寿命**、**弹道预演** |
| 威胁 | 3 | 双方 incoming risk、最近子弹的反射最近接近距离 |
| 回合阶段 | 4 | 交战中 / 结算窗口 / 冻结 / 时钟 |
| 上一次动作 | 3 | `[throttle/2, turn/2, fire]` |

**明确不给**：地图种子与 RNG 状态、对手的内部目标栈、**对手当前按键**（改用速度与角速度，
由环境按上一帧位姿差分——人眼看得到位移，看不到键）、**炮口角度扫描**（扫 36 格等于直接
给「最佳射角」，只给当前角度，找射位仍要靠转身学）、kill field 与 MPC 对候选的评分。

前三项有回归测试守着：固定双方位姿，打乱 RNG、Laika 的目标栈和对手全部五个按键，
断言观测逐元素不变。

### A：动作 —— `Discrete(18)`

```
[throttle, turn, fire]
throttle  0 倒车 / 1 不动 / 2 前进
turn      0 左转 / 1 不转 / 2 右转
fire      0 / 1
```

与 MPC 规划器**同一套候选集**，用引擎自身转速（10°/帧），瞄准靠多帧转身完成。
25 Hz 每帧一决策，无动作承诺、无帧跳。

### R：只有胜负，外加两个修正

全程 0，只在终局结算一次：

| 结果 | 值 |
|---|---|
| 赢 | ≤10 秒 `+1.0`，10→30 秒**对数**衰减到 `+0.5` |
| 双亡 | `0.0` |
| 输 | `-1.0` |
| 30 秒平局 | `-1.0` |
| **平滑分**（叠加在任意结果上） | 动作变更率 ≤13% 得 `+0.25`，对数衰减到每帧都换时归零 |

三个数是有来历的，不是调出来的：

- **平局和输同价**，堵掉历史上纯胜负 `±1` 学出「苟活不开火」（12.4%）的退化解——
  那一版没有时限，苟活是严格最优。
- **平滑分的满分线 13% 是实测的**：Laika 12.9%、MPC 12.7%，两个打得好的控制器落在
  同一条水位上。上限 0.25 是算出来的：加了 `S` 之后要维持「任何胜 > 任何双亡」，
  就要求 `S < 0.5`，取一半留余量。
- **终局只认 `Event::RoundEnd`**，它在首次击杀的 75 帧结算窗口之后才发出，期间在途
  子弹仍可能把胜利改成双亡。

## 2. 为什么放弃了逐帧塑形

在这之前有四轮课程（static-target、walking、pursuit、hunt、shooting-range），每一轮都
把游戏换成一个代理任务——一条走廊、一个靶子、一个要缩小的距离——再把设计预算花在那个
代理需要的塑形项上。每一轮都被下一个 credit assignment 问题推翻，而且每一轮推翻的理由
都成立：

1. **距离变小了是谁干的**——`BFS(我,敌)` 的差分把对方走过来的距离也算成我的功劳，
   实测这个污染在真实迷宫上占 85%。改成反事实归因（冻结对手位置）后有效，但只解决了
   空间归属。
2. **死因可能发生在十秒之前**——子弹寿命 250 帧、可无限反弹、对开火者同样致命，
   「死亡 −300」的责任动作常常是几百帧前那一枪。
3. **稠密塑形和稀疏终局的量级对撞**——第一版塑形整局累计约 −187，撞墙死只扣 −10，
   于是「第 2 帧去死」严格最优，回合长度从 8.9 帧塌到 2.2 帧。
4. **混合地图把 credit 劈开**——观测里带完整迷宫布局，策略能分辨自己在哪张图，
   学出两套各自退化的策略。

duel-v1 的做法是把代理去掉：环境就是真实对战，唯一的信号就是结果。设计预算转移到
观测，这也是仓库自己的第一教训——「信息 > 激励」，补观测两针（弹道预演 +8 点、
导航方向 +3 点）的收益超过整个奖励塑形调参阶段的总和。

完整的已证伪清单在 [`docs/LESSONS.md`](docs/LESSONS.md)。

## 3. 当前进展

对手池 Laika 40% / MPC 40% / 冻结的自我 checkpoint 20%，每局每槽独立掷骰。
冻结档的权重在训练器里（引擎跑不了神经网络），所以环境额外发布 tank 1 视角的观测，
训练器过一遍冻结网络再把动作喂回去——网页上也能选它作对手看实时对战。

最近一次完整评估（v5，848 万步，300 局 argmax）：

| 对手 | 胜 | 负 | 双亡 | 平 |
|---|---:|---:|---:|---:|
| Laika | **57.9%** | 15.9% | 26.2% | 0.0% |
| MPC 规划器 | 35.5% | 33.6% | 29.1% | 1.8% |
| 冻结的自我 | 25.0% | 9.4% | 62.5% | 3.1% |

参照：`LESSONS.md` 记的**纯 PPO 历史天花板是 36.4%**，本分支近期的几个 checkpoint 是
9% / 7% / 5% / 1%。上界是 MPC 的 90.2%。

逐版结果见 [`docs/TRAINING.md`](docs/TRAINING.md)。

## 4. 还没解决的

1. **动作抖动。** argmax 变更率 41%，Laika 是 13%；转向反向 12% 对 1%。平滑分刚上，
   效果待测。如果不够，下一步是**动作承诺**（k 帧内不换）或 CAPS 时间正则——两者都是
   结构层干预，按仓库的三级纪律（补观测 → 改结构 → 加奖励项）优先于继续加奖励项。
2. **自我对战里 62.5% 是双亡**，所有对手里最高。两份同源权重、同样的冲脸倾向。
3. **`V(s)` 到底可不可学。** `LESSONS.md` 第 0 节记着六个受控消融里 R² 全在 0 附近、
   「局面几乎不决定胜负」。但训练中 explained variance 稳定在 +0.90 以上。这两个数字
   需要一个解释——很可能是「对某个固定策略的结局可预测」和「局面决定胜负」不是一回事。
4. **蒸馏。** MPC 的 18 个候选中位有 14 个并列，完美预测器的 top-1 上限只有 11.9%，
   特权老师蒸馏后 action agreement 卡在 22.5%。这条路在历史上反复失败，duel-v1 没有再试。

不是断言。
