# killfield

**[▶ 在线试玩](https://cichlider.github.io/killfield/)**

浏览器里的迷宫坦克对战，配一个搜索型 AI 对手。
纯 ES 模块，零依赖、零构建步骤，克隆下来起个 HTTP 服务就能跑。

---

## 原理

AI 每帧要回答两个问题：**往哪走**，**朝哪开火**。

这张地图里墙很多，直射的机会很少，大部分击杀得靠子弹反弹。
所以常规的「我从这里开枪能不能打中」很难算——要枚举所有角度、逐条模拟反弹。

这里把问题反过来：

> 不问「我能不能打中他」，而问「**子弹可能是从哪些格子飞过来的**」。

具体做法是从敌人所在的格子向外发射一圈反向射线，让它们按墙面反弹传播。
射线经过的格子，就是能打到敌人的格子。统计下来得到一张覆盖全图的密度场——
颜色越深的地方，可行的射击角度越多。

这张场同时解决了那两个问题：

- **往哪走** —— 朝密度更高的格子移动
- **朝哪开火** —— 当前格子里命中角度最密集的那个方向

在此基础上，每次重规划会比较 18 条轨迹：9 条持续移动方案，以及 9 条
「首帧静止开火、次帧起采用不同移动」的方案。每条轨迹都在沙盒里前推 36 帧，
按「是否更接近好射位 / 炮口是否更对准 / 会不会吃子弹 / 开火后能否安全续走」
打分，选最优的首帧动作执行。开火不再无条件覆盖移动与躲避，而是在同一评分中竞争。

游玩页右侧提供一块**实时参数面板**，可以直接调整导航、追猎、开火纪律与风险权重。
修改从下一次规划开始生效，并自动保存在当前浏览器；“恢复默认值”可随时回到仓库中经过
基准测试的配置。观看 AI 对战时不需要停局或重新加载页面，适合快速观察 reward/score
改动是否让局部最优行为朝预期方向变化。

手机进入“和它打”后，画面左侧提供可切换的两套触控移动方式：16 方向世界坐标轮盘，或
传统前进/后退/左转/右转方向键。轮盘指定期望移动方向，坦克会一边转向一边移动；夹角
不超过 90° 时车头对齐并前进，超过 90° 时车尾对齐并后退，不会强迫车头掉转 180°。
右侧是可独立按住的开火键。控制器可用画面上方的“隐藏/显示”按钮收起和恢复。触控层位于游戏舞台内部，
因此点击全屏后仍可双手操作；不支持元素全屏的手机浏览器会自动使用铺满窗口的回退布局。
全屏时会在支持的平台请求横屏；iPhone 可直接旋转设备进入横屏布局。物理与 AI 保持固定
25Hz，画面按手机 60/120Hz 刷新率插值显示；手机版默认使用 256 条搜索射线，避免 AI
规划阻塞画面；网页端射线上限与普通设备默认值均为 512。

## 当前对战基准

既有高精度基准配置下让 KillField（0 号坦克）连续对战 Laika（1 号坦克）1000 局：2048 条射线、
Laika 精确对手模型、固定随机种子 `20260814`，每局主动对战最多 60 秒。完整命令：

```bash
node test/killfield_vs_laika.js 1000 60 20260814 2048
```

| 结果 | 局数 | 占全部对局 |
|---|---:|---:|
| KillField 胜 | **897** | **89.7%** |
| KillField 负（Laika 单独存活） | **52** | **5.2%** |
| 平局 | **51** | **5.1%** |

**最大连胜：45 局。** 平局由 50 次双杀和 1 次 60 秒超时组成；排除平局后的胜率为
`897 / (897 + 52) = 94.52%`。如果只问 KillField 坦克是否被摧毁，则共死亡 102 局，
其中 50 局同时击毁 Laika，按规则计为平局。首次死亡平均发生在 8.44 秒。

基准会完整模拟击杀后的 3 秒结算窗口，因此飞行中的子弹仍能制造双杀；只跳过结算完成后
纯展示用的冻结等待。固定种子的前 100 局另行重跑后精确复现 `88 胜 / 8 负 / 4 平`，
用于确认统计可重复。这个数字描述的是本版本对 Laika 的特定 matchup，不代表对人类玩家
或其他策略的通用胜率。

## 运行

ES 模块不能从 `file://` 加载，起个本地服务即可：

```bash
python3 -m http.server 8000
```

## 结构

```
src/game.js          引擎：坦克、子弹、回合状态机（固定 25 FPS）
src/maze.js          迷宫生成、连通性、距离场、墙体索引
src/laika.js         对照用的脚本 AI 对手
src/killfield/       AI：密度场、候选动作搜索、打分、风险估计
test/                单元测试与行为基准
```

实现细节见 [DESIGN.md](DESIGN.md)。
