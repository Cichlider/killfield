回合结束时结算一次

$$R=R_{\text{outcome}}+S(r),\qquad r=\frac{\text{动作变更次数}}{\text{回合帧数}-1}$$
$$R_{\text{outcome}}=\begin{cases} 1, & \text{胜，}t\le 10\text{s}\\[2pt] 1-\dfrac{1}{2}\cdot\dfrac{\ln(t/10)}{\ln 3}, & \text{胜，}10\text{s}<t\le 30\text{s}\\[6pt] -0.1, & \text{双亡}\\[2pt] -1, & \text{失败，或 30 秒平局} \end{cases}$$
$$S(r)=\begin{cases} 0.25, & r\le 0.13\\[4pt] 0.25\left(1-\dfrac{\ln(r/0.13)}{\ln(1/0.13)}\right), & 0.13<r\le 1 \end{cases}$$

胜负决定任务目标，时间项反对拖延，平滑分表达行为风格。0.13 是实测值：Laika 与 512-ray 规划器在同一动作三元组下的变更率分别为 12.9% 与 12.7%。平滑分上限 0.25 受一条不等式约束——最差的胜（+0.5）必须仍然高于最好的双亡（-0.1+S），因此 S<0.6。

一些问题

01

超参数是怎么定的？

大部分是社区默认值，并且是刻意冻结的。只有四个是从这个环境的性质推出来的。

边界先写：这个项目从未做过超参数搜索。这是有意识的取舍，不是疏漏。主结论是一组消融，而消融成立的前提是超参必须是常量——如果每个 arm 各自调参，比较的就不是注入位置，而是谁调参运气好。协议因此把它冻结：除非某个实验明确研究某一项，否则网络规模、优化器、学习率、步数预算与对手池一律不变。

学习率为什么必须衰减

PPO 是 on-policy，这就是全部原因。学习率太大，策略一步跨出 clip 能兜住的范围，下一批数据就由这个坏掉的策略产生，而且没有 replay buffer 可以救——这种崩溃不是「多训训就回来」。本项目实测过：恒定学习率续训到 6000 万步，约 200 万步时崩塌，再也没有恢复。现在的调度是 lr = 3e-4 × (1 − 血统进度)，entropy 系数按同一个时钟退火。

值得点名的一道疤：热启动如果不把 Adam 状态和调度位置一起带过来，学习率会被静默重置回初值。连续六个 run 都是这样，7800 万步跑在接近恒定的 3e-4 上，而以为调度在衰减。修法是概念上的而不是数值上的——调度归属血统而不是归属这次调用，进度按继承来的 trained_steps 对整条血统的地平线计算。

0.999 是怎么来的，以及为什么最长回合是 875 帧

判平的死线是 DUEL_FRAMES = 750，即 25 Hz 下的 30 秒。但击杀并不结束回合：引擎还要再跑 NUMBEROFFRAMESBEFOREEND = 125 帧，让已经在飞的子弹仍有机会把胜利改判成双亡。所以硬上限是 750 + 125 = 875 帧。奖励只在终局给一次，因此 gamma 必须大到让回合里最早的那个动作还能分到信用。

gamma有效视野 1/(1−γ)开局动作剩余信用 γ^875
0.99100 帧 · 4 秒0.0002
0.995200 帧0.013
0.998500 帧0.17
0.9991000 帧 · 40 秒0.42
0.99952000 帧0.65
判据是有效视野要盖过最长回合：1/(1−0.999) = 1000 帧 > 875 帧。0.42 是结果而不是目标——它就等于 e^(−875/1000)。而更常见的默认值 0.99 会让一个回合的前 20 秒完全没有学习信号。

为什么不用 gamma = 1：紧迫感已经写在奖励里了，赢的价值从十秒的 +1.0 对数衰减到终场的 +0.5。再用小 gamma 制造时间压力，是同一件事收两遍费，会把策略推向过早的交换。而且在终局才给奖励、critic 几乎解释不了什么的情况下，无折扣回报的方差也更大。诚实的缺口：3e-4、0.2、0.95 这些值从未在本环境验证过，也没有做过 sweep。

02

PPO 的训练循环到底在做什么？

采集 256 个环境 × 128 步，算 GAE，然后把这一批数据复用 4 轮、做 32 次梯度步。

一句话：PPO 是 on-policy 的 actor-critic，用新旧策略的概率比值加上 clip 来限制一次更新能走多远，这正是同一批数据可以安全复用几轮的原因。

阶段做什么本项目的数字
① 采样用当前策略采样动作推进环境，存下观测、动作、旧策略给这个动作的 log 概率、V(s)、奖励与 done。256 × 128 = 32,768
采样而非 argmax，on-policy 的要求
② 算优势从后往前走一遍：delta = r + γ·V(s′)·alive − V(s)，再 gae = delta + γ·λ·alive·gae。returns = advantages + values。γ = 0.999 · λ = 0.95
③ 展平拉平成一个批，并对优势做标准化，让 loss 的尺度与学习率解耦。32,768 条
④ 更新打乱、切成 minibatch，在 clip 目标加上 value、entropy 与两个附加项上做梯度步。4 epochs × 8 minibatches = 32
每批 4,096 条
⑤ 收尾按血统推进学习率与 entropy 调度，发布 checkpoint，回到 ①。每 1,048,576 步发布一次

clip 在干什么

on-policy 的数据只对采集它的那个策略有效，但每批只用一次太浪费，所以 PPO 复用四轮。从第二轮起，网络已经不是采集数据的那个网络了。exp(new_logp − old_logp) 这个比值衡量的正是这个偏离：等于 1.0 说明没变，1.3 说明这个动作的概率涨了 30%。把它 clip 在 [0.8, 1.2]，超出部分梯度直接为零，一批数据就不会把策略一口气甩出去。取 min 而不是直接 clip，是为了保持悲观——过度积极的改进会被截断，但策略还在往错方向走时不截断，修正的梯度要留着。TRPO 用 KL 约束加二阶优化实现同一个信任域；clip 是去掉了 Fisher 矩阵的一阶近似。

三个非教科书的地方

critic 预热前 20 个 update 的 loss 只有 value loss，policy 完全不动。resume 的 run 跳过这一段：它的 critic 是在同一个奖励上训出来的，并不陈旧。
所有终局都切断 bootstrap包括 30 秒平局。平局在这里不是 truncation，而是带着自己 −1.0 奖励的真终局，所以切断 bootstrap 在本任务中是定义上正确的。把这段代码原样接到 Gymnasium 的 TimeLimit 上则会出错。
两个附加项放在 loss 里而不是 reward 里persistence 与 wall 两项直接对概率质量施压：不延续上一个移动的质量，以及撞墙后仍重复同一油门方向的质量。终局风格分只是一个标量摊到约 200 帧，而 entropy 是作用在 logits 上的稠密解析梯度，这是一场不公平的对抗；把这一项搬进 loss 才是平等的战场。

证据等级照实说：GAE 数值对拍、termination / truncation 单测、单状态收敛测试与同机 LunarLander / CleanRL 对照都还没做，所以本页不宣称这套实现已被独立验证。已经核查过并且正确的是一处边界约定：env.step(action) 之后，done_buf[t] 记录的是 transition s_t,a_t → s_t+1 是否终止，所以 alive = 1 − done_buf[t] 既没有早一帧也没有晚一帧。另有一个已知缺陷是公开而不是悄悄修掉的：value loss 写成 0.5·MSE 后又乘以 0.5 的 value 系数，这是一次无意的双重折半，有效权重实为 0.25·MSE。

实际碰到的问题

症状测到的事实怎么处理
纯 PPO 打不动两个 run 只有 1.6% 和 5.9%；前身项目里纯 RL 的历史天花板是 36.4%，而手写规划器是 96%。不蒸馏规划器的动作——它 18 个候选里中位 14 个并列，完美预测器的 top-1 上限只有 11.9%。改为把它的短视野预演压成 9 个安全值放进观测。
只给胜负 ±1 学成苟活12.4%，学成一个不开火的退化策略。重排终局尺度：赢随时间从 +1.0 衰减到 +0.5，双亡 −0.1，输与 30 秒平局同为 −1.0。
恒定学习率不可逆崩溃续训到 6000 万步，约 200 万步时崩塌，再未恢复。沿血统线性退火到零，entropy 同步，外加 20 个 update 的 critic 预热。
扩观测可能砸掉已有能力schema 21 到 26，共五次扩容。函数保持迁移：新列补零，actor 新通路从 α=0 起步，并要求 step-0 的 logits 与旧模型逐位相同。
自博弈池静默塌缩成一个成员不传冻结祖先参数会回退到初始化 checkpoint，于是 1678 万步里 80% 的自博弈全在打同一个模型的一个副本。唯一的提示是日志里一行 frozen league (1)。显式指定祖先档；用 resume 反而安全，因为它无处可回退，会直接报错。
按参数名判断架构同一类 bug 触发四次。最严重的一次：对旧参数名的 hasattr 判据失效，dodge 根本没有传进 forward——页面上展示的是一个主通路被切断的模型，而它训练时这条通路的门控在威胁帧上均值是 8.24。改用每个 duel 网络都带的架构级标识，模型一律从 manifest 重建，并立刻验证：把同一个真实 checkpoint 载入新旧两种架构，要求 logits 最大差为 0.0。
100 局评测足以颠倒结论同一个 checkpoint，100 局 76.0%，1000 局 66.8%。而组间真实差距常常只有 1–3 分，远在噪声之下。工程验收口径从 100 局改为恰好 2000 局。
座位不对称同一个模型自己打自己只有 38.9% 而不是 50%：座位本身约值 11 个百分点。所有头对头以 38.9% 为基准读，确认实验双向交换座位。

怎么排除「只是训练步数上来了」

控制它堵住的解释
同起点所有 arm 从同一成熟祖先续训，五个 arm 的 step-0 logits 与 value 已验证逐位相等。没有可继承的领先。
同预算每个完成的 arm 都从 trained_steps=404,881,408 开始，恰好追加 4,194,304 步，停在 409,075,712，并处在同一条 600M 步学习率 / entropy 调度的同一区间。步数是常量，差异不可能来自训得更久。
同对手池50% Laika 加 50% Killfield，刻意关掉自博弈，避免漂移的对手污染因果比较。
等参数、等算力的负对照shuffled arm 用整段训练固定不变的一个置换，把 9 个分数与 9 个动作的对应关系打乱。它把「多了九个数」和「对齐到了正确动作」拆开，没有别的办法能做到这件事。
比曲线，不只比终点学习曲线 AUC，横轴归一化、所有 arm 用完全相同的评估间隔，堵住「只是收敛早晚不同」这一读法。它的 per-seed 离散度比终点小得多。
统计单元是训练 seed不是那 2000 局。三个种子足以暴露明显不一致，不足以给出紧的总体估计；区间重叠的结果按不确定报告。
预注册并打时间戳GO / NO-GO 规则冻结在第一个受关注的 arm 开跑之前。确认实验一律使用最终 checkpoint，不做任何基于性能的挑选；崩掉的 run 按失败记录，不拿中途某个更好的 checkpoint 顶替。
二进制锁定每个 run 记录训练所用引擎二进制的 SHA-256，评估器拒绝比较 SHA 不一致的 checkpoint。

还有一项检查落在训练池之外：同样的 arm 对两个从未出现在训练中的祖先各打 600 局。排序原样复现——observation、dual、shuffled 聚成一簇，none 与 shortcut 聚在下面——这排除了「效应只对两个训练对手成立」的读法。

反例：一个被本项目自己判死的好看结果

把常数信任标量换成状态条件门控，从 v16 热启动再训 16,777,216 步，对 Laika +2.7 分，对 Killfield +11.2 分，对一个未参训祖先 +18.0 分。这些数字一个都没有被当作证据，因为没有匹配的对照臂。热启动重置了 Adam 状态、学习率按新调度回到 6.12e-05，所以「v16 再训 1678 万步」这件事本身就可能解释全部提升。量级也对不上：本项目所有匹配消融给出的 actor 通路增量是 +1.23 / +2.33 分，一个值一到两分的机制不会突然给出十一到十八分。能定案的对照——v16 原样、同样 1678 万步、同样对手池——没有跑过，所以门控不进入任何主张。

同样的纪律适用于推理期移除。在固定权重上关掉一条通路，测的是这个 checkpoint 依赖它多少，不是这条通路是否必要：一个从一开始就不带它训练的 arm，可以把同样的信息经 trunk 路由，并落到同一处。把依赖度变成必要性，需要删掉通路后重新训练到收敛，这件事没有做。

另一个问题：当前 v17b checkpoint 是否依赖这条通路？

一个机制假说——是论证，不是实验结论

entropy 是策略那个 18 类 softmax 的离散度，按状态平均：ln 18 = 2.890 是均匀，0 是完全确定。最好用的读法是 exp(H)，即策略实际上还在几个动作之间犹豫。这一代训练到末尾，采样策略的熵大约是 H ≈ 0.23——约 1.26 个等效动作，最大动作上大致有 0.97 的概率。这么锐的策略，不会被一个小的加性偏置推动。

同一幅图在 logit 空间里，在 8,192 个真实状态上实测：trunk logits 的标准差是 9.284，绝对值 P90 是 15.680。一条加性偏置要改变 argmax，必须跨过这个落差。dodge 那条跨得过去——它自己的贡献在 P90 上达到 4.226——这正是移除它会损伤当前 checkpoint 的原因。但只要那 9 个值在共享观测里可读，trunk 自己也能造出同样的偏置，这与 observation 臂拿走几乎全部收益、而 dual 与 shuffled 打平这一事实一致。四条开火捷径则从未达到让这个问题成立的量级。

按正确的证据等级表述：端点打平是实测的；关于「为什么」的熵与 logit 跨度解释是用实测量搭起来的论证，不是实验。受控检验应当训练一个刻意维持高熵的 arm，看对齐通路是否就此产生价值。这个实验没有跑过。

这为什么不必与 residual policy learning 或动作先验那条线矛盾：那些设定通常是在起点很低的固定经典控制器之上加残差，而且多是连续控制。这里的底座是一个联合训练了数亿步、且已经能通过共享观测看到同样信息的网络，动作空间是会收敛得很锐的离散 18 类 softmax。这个阴性结果是对那套直觉在本设定下的边界检验，不是对它的普遍否定。

「搜索只生成局部特征」经得起逐维清点吗？

严格口径 53 维依赖前向模拟；宽口径计入几何搜索后为 76 维。

边界先写：Hybrid 不读取 Killfield 的 512-ray 密度场，但确实消费规划器式的中间计算。严格按弹道 / lookahead 口径，10 维瞄准辅助 + 30 维逐弹预测 + 4 维威胁摘要 + 9 维 dodge，共 53 / 1028（5.16%）；再计入 16 维墙体射线与 7 维 BFS 路径 / 梯度 / 死路量，宽口径为 76 / 1028（7.39%）。密度场相关通道为 0。

证据支持的贡献是：把 action-conditioned lookahead 输出作为观测信息，在匹配续训中带来 +9.53 / +7.30 pp；再把这些输出直接接到对应动作 logits，没有可测增益。学习策略是在消费规划器式中间产物后超越完整规划器，而不是「学习超越规划」。
08

AI 赢人类靠的是反应速度吗？

游戏重站位与弹道预埋；但正式评测仍是零帧延迟。

边界明确：正式评测使用零帧延迟。viewer 提供 1/2/3 帧档位，但尚无正式对照；3 帧是 120 ms，仍短于约 200 ms 的人类反应量级。并且零延迟训练的策略按 40 ms 动作预算校准，推理时改成三帧是分布偏移，不只是「同一策略慢一点」。干净证据需要把延迟做成训练域随机化维度或写入观测。

机制上，Tank Trouble 不是精确瞄准游戏：转向慢、反弹弹道持续存在、弹药有限、迷宫墙体使站位、封锁与弹道预埋成为核心。这说明反应速度不是唯一变量，但不能消除零延迟混淆。

浏览器中的一帧

  1. requestAnimationFrame 累计真实时间；每满 40 ms 触发一次物理 tick。
  2. 保存上一份可渲染状态，供稍后插值。
  3. WASM 从权威状态编码 observation、bullet mask 与 dodge_safety。
  4. Hybrid 在本地前向、取 argmax，并把动作写回引擎。
  5. 对手决策；双方动作同时消费，物理推进。
  6. 客户端读取新状态，处理声音与终局事件。
  7. 渲染在两份权威状态间插值；刷新率只改变平滑度，不改变 25 Hz 规则。
