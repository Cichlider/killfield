02

actor 是什么，你对它做了什么？

三类编码器汇入同一 trunk；actor 把它变成 18 个 logits。六条零初始化捷径重新参数化了学习问题。

它是什么

Actor 是策略网络里负责做决定的那一半。共享编码器先把地图、子弹集合和其余标量压成一个状态表示；actor 把它变成 18 个 logits，softmax 再变成动作分布。训练时从这个分布采样以保持探索，评估和本页取 argmax 以获得可复现的行为。Critic 读同一份表示，但只输出一个标量——它对当前局面价值的估计。

我做了什么

六条动作对齐的软捷径，每条把一个已经算好的事实直接接到它所关心的那些 logit 上：

捷径直接连接表达什么
dodge_scale9 个 dodge_safety 值 → 各自对应的不开火 / 开火两个 logit「候选 3 的安全值说的就是移动 3」——索引对应关系本身
ammo_scale剩余弹槽 → 9 个开火 logit整体上愿不愿意花一个弹槽
shot_quality_scale预计命中且 ETA 短 → 开火 logit偏好能快速释放弹槽的射击
ammo_lock_scale弹药稀缺度² × 预计占槽时间 → 开火 logit弹夹越空，越反对长期占槽的射击
suicide_scale当前弹道的自杀风险 → 开火 logit不要开一枪已知会打死自己
idle_logit_penalty超过 8 帧的连续中性移动 → 两个中性动作允许战术停顿，逐渐反对无限期发呆（最多 −4.0，永不 mask）

为什么有效

不是因为它们替模型写好了策略，而是因为它们重新参数化了学习问题。

拿 dodge_safety 举例。加捷径之前，9 个安全值与 18 个动作的对应关系藏在 128 维共享瓶颈之后。稀疏的胜负信号必须同时学会两件事：哪个数对应哪个动作，以及这个数该信多少。前者是关于索引的固定事实——它永远不会变，却要从奖励里昂贵地发现。对齐之后，网络只剩第二个问题，而那是每条捷径一个标量。

dodge_scale 从 0 起步，v12 学到约 0.189，到 v15 达到 1.361——正是实机出现明确躲弹行为的那一版。模型没有被告知要躲；它只是被告知哪个数字指的是什么，然后自己决定了该信多少。

它们始终是 bias 而不是规则：trunk 仍可用别的证据覆盖，任何一条都不 mask 动作。每条捷径都零初始化——α=0 时新网络的 logits 与旧 checkpoint 逐位相同，这正是它们能在血统中途安全加入的原因。

搜索只生成局部生存特征；最终的权衡与动作选择仍由学习策略完成。

03

训练流程是什么？loss 是什么？

256 个环境 × 128 步 = 一次更新。五项 loss，其中两项专门修 reward 够不到的优化病理。

一次更新

训练并行运行 256 局真实游戏。策略读取每个环境的观测，从分类分布中采样动作；引擎执行它并产生下一帧。每个环境累计 128 步后，终局奖励与 critic 的价值估计进入 GAE；整批打乱成 8 个 minibatch，优化 4 个 epoch。也就是每次更新 32,768 个 transition、32 次 optimizer step。

32,768 transitions并行环境采样；训练时 sample，评估与网页使用 argmax。

loss

$$\mathcal L=\underbrace{\mathcal L_{\text{clip}}}_{\text{策略}}+\underbrace{0.5\,\mathcal L_V}_{\text{价值}}-\underbrace{\beta_H\mathcal H(\pi)}_{\text{探索}}+\underbrace{0.02\,\mathcal L_{\text{persist}}}_{\text{抖动}}+\underbrace{0.05\,\mathcal L_{\text{wall}}}_{\text{顶墙}}$$
项它做什么
PPO-clip提高高优势动作的概率、降低低优势动作的概率，但把 ratio 裁到 [0.8, 1.2]，使单次更新无法让策略突变。
value · 0.5训练 critic 预测从此处出发的回报——正是它把原始奖励变成 actor 可用的低方差相对判断。
entropy · β阻止分布过早变尖。β 从 0.01 按调度衰减。
persistence · 0.02惩罚「与上一帧不同的移动」上的概率质量。只比较 movement = a // 2，故意忽略开火位。
wall · 0.05只在真的发生硬碰撞时，惩罚继续维持刚才那个撞墙的油门。贴墙过弯不受罚。

为什么抖动是 loss 问题，不是 reward 问题

这是我认为最值得讲的一段。Reward 回答的是「整局什么结果值得追求」，loss 决定的是「这一次参数更新具体朝哪个方向走」。两者不是互相替代。

抖动是分布在逐帧尺度上的形状问题。从分类分布采样时，即使 argmax 从不改变，只要分布仍然平坦，动作就会每帧跳变。对比作用在这个平坦度上的两股力量：

力量到达 logits 的路径时延方差
终局平滑分reward → return → GAE → advantage → clip 项 → logits约 200 帧高——责任要靠猜
entropy 项解析梯度，直接作用于 logits每一帧无

所以这场竞争在结构上就不对等。平滑分要穿过约 200 帧，再通过稀疏的 credit assignment 猜出哪一次切换才是坏的——而 entropy 每一帧都在用精确梯度把分布重新推平。把平滑分调大解决不了这个问题；那只是在给一个本来就输在时延上的信号增加方差。

persistence 直接读取当前这一帧策略在 18 个动作上的概率，把「与上一帧不同的移动」的质量求和并惩罚。不用等回合结束，不用 critic 猜是哪一帧的责任。实测：采样动作变更率 66% → 54%，继续训练后接近 15%；转向反转率 22.6% → 0.6%。

但这也暴露了 loss 的危险之处。满足「保持上一个动作」最容易的方式是根本不动。persistence 上线后，长期静止从 18.4% 升到 48.0%。而修法也不在 loss 里——我们没有把「不动」设成非法动作，而是把它交给 actor，做成延迟生效的软偏置：前 8 帧中性移动完全免费，之后 logit 才开始下降。

loss 的四次显式修订

把标准 PPO 记作 L0，显式 loss 结构共改过四次。reward 改动、学习率调度修复、actor 捷径和对手池变化都不是 loss 改动——把它们混在一起说「我调了十几次 loss」，只说明因果归因从没做过。

verrun改动目的结果与后续决定
L0v1clip + 0.5·value − β·entropy学会胜负策略并维持探索能学，但终局平滑分压不住逐帧采样抖动。
L1v9+ 0.02 persistence，最初比较完整动作直接惩罚不延续上一动作的概率质量切换明显下降。同时制造「不动」捷径，并把松开扳机误算成一次切换。
L2v10+ 0.05 reversal；瞄准时只保留 25% 压力专门压制左转后立刻右转末期 reversal mass 约 0.17%——但静止问题没改善。该项后来被移除。
L3v11去掉 reversal，加 + 0.05 wall只在真的硬碰撞时反对同一油门wall 概率质量 0.92 → 接近 0；实测硬撞墙率约 0.8%。
L4v16persistence 只比较 movement = a // 2，忽略开火位平滑移动，但不鼓励按住扳机松开扳机不再算作坏切换。这就是当前的 loss。

两个存活下来的行为项，写全是：

$$\mathcal L_{\text{persist}}=\mathbb E_t\!\left[1-\sum_a\pi(a\mid s_t)\,\mathbf 1\{m(a)=m(a_{t-1})\}\right],\quad m(a)=\left\lfloor a/2\right\rfloor$$
$$\mathcal L_{\text{wall}}=\mathbb E_t\!\left[\mathbf 1\{\text{hard-hit}_t\}\sum_a\pi(a\mid s_t)\,\mathbf 1\{\tau(a)=\tau(a_{t-1})\}\right]$$

hard-hit 只对应完全撞停的 hit_something，故意不含 wall_sliding——那是坦克正常过弯的方式。m(a) 是 9 种移动，τ(a) 是 3 档油门。

06

如何为下一代热启动？

同时做两件事：学习者继承函数，父代变成冻结对手。step 0 时 logits 逐位相同。

这里的「下一代」不是清空网络重练，而是同时完成两件事：学习者继承上一代的函数，上一代本身变成冻结对手。前者保存能力，后者给新一代一根不会随训练漂移的横杆。

同构续训直接恢复 checkpoint 就行。真正需要设计的是观测或 actor 结构发生变化时——怎样让新网络在 step 0 与旧网络严格等价。

1 · 观测扩容：只追加，补零

$$z=Wx+b\;\longrightarrow\;z'=[W\;\,0]\begin{bmatrix}x\\u\end{bmatrix}+b=Wx+b=z$$

新特征 u 已经可读，但初始化瞬间的贡献严格为零；之后再由梯度决定是否使用它。这要求新维度只能追加——不能插进中间，也不能改变旧通道的语义。schema 20→24 的每一步都遵守它，旧祖先也用同样方式升到当前 schema，因此可以继续进联赛而行为不变。

2 · Actor 新通路：尺度从零开始

$$\ell' = \ell + \alpha\, g(s),\qquad \alpha_0=0$$

无论 g(s) 是 9 个安全候选、弹药稀缺度还是射击 ETA，α=0 时 18 个 logits 与旧模型逐位相同。v12 的 dodge_scale、v15 的 ammo_scale、v16 的三条射击质量尺度都是这样处理的。

v14 是有意的例外。idle_logit_penalty 以 4.0 启动，因为它的目的正是在 step 0 就改变长期静止行为。我们先用固定对照确认了软偏置没有破坏基础能力——但这一版不能宣称「actor 函数完全不变」，论文必须讲明，而不是把它悄悄混进其他版本里。

reward 改变+ 20 次 critic-only 预热旧 critic 预测的是旧回报定义。先让它重新标定，再允许 actor 依据其 advantage 更新。

阶段结束时，模型带 schema、步数和版本号原子保存。新学习者从它热启动；同一份快照加入 AncestorPool，之后只做推理。每局抽一个祖先，较新的权重更高，但旧的从不删除。于是新一代既要打赢最新父代，也必须保住打赢祖父所需的东西——这正是打断「克制父亲、忘了祖父」循环的机制。

验收：用同一批固定观测同时跑新旧网络，要求 18 个 logits 的最大绝对差为 0。再检查 schema / observation / action manifest，再跑浏览器与 PyTorch 的 parity case，最后记录 step-0 行为基线。做完这些，后续变化才能归因于训练，而不是迁移时把权重接错了。
07

交付了什么？客户端里一帧怎样发生？

六类产物围绕同一套权威物理。然后是一帧的确切顺序，以及三种被混为一谈的延迟。

Hybrid checkpoint 只是六者之一。真正交付的是一条从权威游戏规则、经训练与模型、经验证、到浏览器里跑起来的闭环。

产物形态负责什么
统一引擎Rust crate · 原生动态库 · WASM随机迷宫、坦克运动、碰撞、反弹弹道、回合判定。训练、评估、网页共用同一套权威物理。
Killfield 规划器引擎内的 512-ray 密度场与滚动规划器靠实时搜索选动作，从不训练。既是对手，也是 Hybrid 的能力参照。
Hybrid 学习策略PyTorch checkpoint · 浏览器 json + f32 bin把 1028 维观测映射到 18 个 logits，并经 actor 捷径组合躲避、弹夹与停顿偏好。
训练系统向量化环境 · PPO · GAE · 祖先联赛 · checkpoint 发布器并行采样、优化 actor–critic、热启动升级、保存训练血统。
评估与验证固定对手评估 · 动作诊断 · 性能基准 · schema / parity / 物理回归衡量胜率、双亡、抖动、撞墙、延迟，以及跨端一致性。
浏览器产品Watch 客户端 · 这篇交互式论文把相同物理和相同模型交给读者，并把内部状态变成可解释的演示。
工程上最重要的一条：训练环境、原生评估和网页展示没有各自复制一套游戏规则。同一个 Rust 引擎编译成原生库供 Python 训练，也编译成 WASM 供浏览器使用；checkpoint 导出为网页权重后，再用固定 parity case 检查——浏览器的 logits 必须与 PyTorch 一致。

一帧的顺序

页面启动时，WASM 引擎与模型 manifest / 权重并行加载。两者就绪后，客户端校验 schema = 24、observation = 1028、actions = 18。任何一项不一致就拒绝启动——而不是让旧模型在新观测上「看起来还能跑」。之后才创建对局。

  1. requestAnimationFrame 累计真实经过时间。累计满 40 ms 才产生一个 25 Hz 物理 tick。
  2. tick 开始前保存上一份可渲染状态，供稍后插值。
  3. WASM 从当前权威局面编码 Hybrid 的 observation、bullet mask 和 dodge_safety。
  4. Hybrid 在浏览器本地完成一次前向，取 argmax，把 action index 写回引擎。
  5. kf_step 开始：Laika 或 Killfield 在引擎内部决策，然后统一消费双方动作并推进物理。
  6. 客户端读取新的坦克、子弹、比分与回合状态，处理声音与回合结束事件。
  7. 屏幕刷新时，在上一份与当前权威状态之间插值。60 / 120 Hz 只让画面更平滑，不改变 25 Hz 的规则。

切换对手时界面立即给出选中反馈，然后重建一局；WASM 与权重已在内存中，不会重新下载。暂停会清空累计时间，恢复时不会突然快进一串旧帧。
