## 2026-08-20 — 项目重启，引擎移植到 Rust

### 起因

上两个项目（`~/tank_trouble` Python 41 个实验、`~/killfield` JS）已经把
「用搜索打赢这个游戏」走到头了：MPC 96%、特权 MPC 100%、最好的纯网络 88.2%，
而 **PPO 纯 RL 线的天花板只有 36.4%**。killfield 的 PPO 更是 1.6% / 5.9%
就被掐掉，两个 run 都没收敛。

现在目标变成**面试 RL 岗位**，面试官要看的是完整的 RL 流程、奖励塑形和流水线管控。
如果重做一遍还是打胜率，会第三次推导出「搜索碾压 RL」，RL 依然是配角
——这对 RL 岗面试是自杀。所以目标改成**「像人」**。

### 定下来的方向

**「像人」的准确定义**（第一次理解偏了，纠正过来的）：不是模仿人类数据分布，
而是 MPC 已经初具人形，但**局部有几处明显不像人的行为**，要用奖励塑形逐个改善。
所以不需要采集人类数据，也不需要 GAIL/判别器那条线。

已识别的「不像人」的点，按性质分类：

| 行为 | 事实 | 归类 |
|---|---|---|
| 机会一出现 40ms 就响应 | MPC 是「4 帧承诺 + 机会中断」，中断 1 帧响应；人类 200–250ms | 结构 |
| 转向吸附 10° 栅格 | `game.js:379-386`，离散控制器才吸附 | 结构 |
| 绝不边走边射 | `maskMovingFireScores` 残留：屏蔽 08-03 加，子弹「未反弹不自伤」08-07 改，理由已失效 | 动作空间 |
| 抖动 | 冠军 iter05 40 局里 `stutter_stall` 246 次 | 结构 |
| 错失开火窗口 | `missed_fire_window` 328 次 | **先查是不是看不见** |
| 击杀后僵住 | P41 已知回归：risk 不算在途子弹 | 观测缺陷 |

**干预顺序不能乱**：① 补观测 → ② 改结构 → ③ 加奖励。
这条来自五次独立失败（P13/P14/P27macro/P27c/P26v10），教训原话是
「已收敛策略的单点矫正会破坏自平衡」。

**DLC 构想拆成三层**（原始想法是「把 killfield 的 score 搬进环境、重新定义胜利」，
我反驳了一半）：

```
基础层：killfield 复刻（原版规则，唯一验收环境）
   ├── 塑形层：Φ 势函数（Ng 1999，可证明不改最优策略）    ← 默认开
   └── DLC 层：改规则的训练环境（课程学习）              ← 可选
           纪律：训练可以在这跑，验收必须回原版
```

反驳的两点：一是「重新定义胜利」属于改变目标不是奖励塑形，会被 Goodhart 钻空子，
而 v2 的「同归于尽骗术」已经吃过一次；二是**手写评分函数正是搜索的做法**，
奖励里写得越细，RL 的贡献越小，面试官越会问「那为什么不直接搜索」。

七项想引导的行为里，**四项可以用势函数免费拿到**（寻敌/走位/瞄准/弹夹管理），
一项是观测问题（反弹计算），只有两项需要冒险的塑形（远距离击杀/枪线压制）。
`field.rs` 的 `guidance_envelope` 天生就是合格的 Φ：每个可达格正值、沿最短路严格上升。

### 语言决策（改判过一次）

最初基于「移植要两周」推荐 JS。**该约束被撤销后结论反转到 Rust。**

推翻我自己的关键数据：killfield 的桥是 4100 env-steps/s = 244 μs/step，
但 `game.step()` 本身只有 5–20 μs —— **引擎只占 5–8%，92% 是观测编码**
（击杀密度场，2048 射线，12.2ms/次重建）。所以 Rust 端口必须**连观测编码器
和密度场一起 port**，不能只 port 物理。密度场是 ray marching，正是 Rust
相对 V8 优势最大的负载。

Rust 的附加价值（和速度无关）：PyO3 让 Python 直接 import、零拷贝 numpy、
消灭「维度错位静默截断」这一整类 bug；rayon 真多线程无 GIL；
wasm-bindgen 让同一份引擎进浏览器。

最后一条今天已经兑现了，见下面的查看器。

### 做了什么

把 `~/killfield` 的 JS 实现完整移植到 Rust，**4,900 行**：

```
rng · constants · maze · game        引擎
ballistics · laika                   对手 AI + 从 Laika 里拆出的弹道预言机
field · risk · chain · tuning        MPC 的四个部件
score · sandbox · teacher            MPC 主体
wasm                                 浏览器入口
```

两处结构性改动，都是行为等价的：

- **`mirror.js` 去掉了**。JS 用 getter 代理做了个「坦克 0/1 互换」的视图，
  好让 agent 永远称自己为 `tanks[0]`。Rust 没有便宜的等价物，改成 sandbox
  接收 `me` 索引、自己重排。结果相同，少一层间接。
- **每回合不变的重数据放进 `Arc`**（迷宫/墙/墙格/距离场/死胡同）。JS 靠引用共享，
  Rust 里每个 sandbox 都 clone 会致命——单是 `distances_for_maze` 就超过 100KB，
  而 MPC 每次重规划建 18 个 sandbox。实测 Arc 的开销：没有。

### 验收标准（这条值得单独记）

**不要求和 JS 逐位相同。** V8 和 Rust 的 `cos`/`sin`/`hypot` 有最多 1 ULP 差异，
一旦 Rust 成为唯一仿真器，这个差异既无害也无法消除。
（专门做过实验：`libm` crate 也对不上——cos 1.1% 不同、hypot 53.6% 不同。
实验结论记下来了，代码删了。）

改成三条：

1. **Rust 自一致** — 同种子跑两次字节相同。这才是 RL 真正需要的性质。
2. **短期逐帧一致** — 和 JS 逐帧相同的时间长到任何逻辑错误都会暴露。
   实测：引擎 947 帧、Laika 3464 帧、密度场**完全位精确**。
3. **结构等价** — 整段运行的离散事件计数完全相等、Laika 目标类型零分歧、
   **MPC 选中动作零分歧**。

第 3 条是关键。750 帧 MPC 对局里，1e-13 的三角函数噪声**一次都没翻转过 argmax**，
坦克位姿和子弹位置逐位相同。

移植期曾用一条命令完成完整对拍；旧 JS 基准和一次性工具已经删除，结果保留在 Git 历史中。

### 抓到的坑

移植时踩到、别人也会踩的：

- **`Math.round` 半值方向不同**。JS 向 +∞（`Math.round(-2.5) = -2`），
  Rust 远离零（`-3`）。Laika 有两处用它对齐 10° 栅格，直接抄会改变行为。
- **NaN 冒充 JS 的 null**。`findDeadEnds` 用 JS 真值判断，`null` 和 `0` 都是假。
- **`for(...; i++)` 的 break 不自增**。`postKillSurvivalScores` 里 `elapsed`
  参与死亡计分，翻译成 `while` 时差点写错。
- **JS 的 `Instant` 在 wasm 上会 panic**。`std::time::Instant` 在
  `wasm32-unknown-unknown` 上不可用，规划延迟遥测在浏览器里报 0。

参考实现里的 bug，**按原样复现并标注、没有修**：

- `action_self_hits` 比的是坦克的 `number` 字段而不是索引，所以在镜像视角下
  （agent 开 1 号坦克）自弹守卫**静默失效**。

### 量到了什么

M5 单线程。

| | 参照 | Rust | 倍数 |
|---|---|---|---|
| 裸引擎 | Python 6–12k 帧/s | **666k 帧/s** | 55–110× |
| 引擎 + 2 Laika | — | **345k 帧/s** | — |
| 密度场 @2048 射线 | JS 12.2 ms | **1.14 ms** | 10.7× |
| 密度场 @512 射线 | — | **0.47 ms** | 26× |
| MPC 单帧规划中位 | JS 0.56 ms | **0.064 ms** | 8.8× |
| MPC p95 | JS 15.8 ms | **2.05 ms** | 7.7× |
| 1000 局 MPC vs Laika | JS ≈ 15 分钟 | **2.0 分钟** | 7.3× |
| wasm（浏览器） | — | 原生的 85% | — |

密度场的 10.7× 是三步优化换来的，**每一步都在位精确对拍保护下做的**：

| 步骤 | @2048 | 累计 |
|---|---|---|
| JS 基线 | 12.2 ms | 1× |
| 忠实移植 | 4.50 ms | 2.7× |
| `nearest_wall` 单趟 + 倒数 | 2.39 ms | 5.1× |
| `nearest_wall` DDA 桶行走 | 1.47 ms | 8.3× |
| `WallGrid` HashMap → 密集 CSR | **1.14 ms** | **10.7×** |

一个反直觉的发现：**除法不是瓶颈**。原以为 1470 万次除法是主因，
改成倒数后几乎没变，真正的收益来自去掉第二趟扫描和空间加速。
最后一步是意外之喜——`maze.js` 自己的注释说 `wall_hit` 是「整个仿真里最热的函数」，
换成密集网格后引擎也快了 37–75%（Laika 提升最大，它的 `checkBulletPath`
每次跑 84 轮弹道）。

### 一个可以直接用的结论

**射线数 512 是甜点。** 1000 局双种子基实测：

| 射线 | 种子段 900k | 种子段 400k | 场重建 |
|---|---|---|---|
| 2048 | 89.7% | 89.0% | 1.293 ms |
| **512** | **90.2%** | — | **0.470 ms** |
| 128 | 88.9% | 87.9% | 0.171 ms |

512 和 2048 战力等同（差 0.5 点），128 在两个种子基上都低约 1 点。

**但降射线不会让 MPC 变快**：2048 跑 1000 局 120.59s，512 跑 121.15s，一样。
MPC 循环里场只占 2–5%，大头是 18 条 rollout × 36 帧沙盒推演。
**射线数只对 RL 观测有意义**，那里没有 rollout，场就是全部成本。

这张表本身也是个里程碑：`LESSONS.md` 里写着「正式结论必须 1000+ 局新种子 +
第二种子基复现」，在 JS 上那是每次 30 分钟所以很难坚持；现在是 4 分钟。
**这条纪律第一次真正被执行。**

### 浏览器查看器

验收方式是「看录像下判断」，所以在做观测设计之前得先有播放器。
选了 wasm 而不是回放文件：浏览器里跑的**就是训练用的同一份 crate**，
没有第二份引擎就没有漂移的可能。

**没用 wasm-bindgen。** 接口面小到只需要 9 个 C-ABI 函数 + 一个扁平 f32 buffer
（2KB/帧），JS 直接从线性内存读，零序列化、零构建工具。
模块 **144KB、零 imports**。

三种模式：观战（MPC vs Laika）、游玩（你 vs MPC）、自对弈（MPC vs MPC）。
人类输入走引擎的连续路径，所以玩家**不吃 10° 栅格吸附**；
面对人类的 MPC 也自动切到 L1 对手模型（冻结对手当前按键），
因为它没法诚实地脚本化一个真人。

右侧面板显示两个控制器的当前动作、决策类型、规划延迟中位/p95、猎杀链、场重建次数。
这是 review 界面的雏形。

## 2026-08-20（续）— 观测编码器、teacher 数据、BC 管线

### 观测是什么（讲人话版）

**agent 看不见画面。** 你玩的时候眼睛看屏幕，它不行——它每次做决定时，
只能拿到 **242 个数字**。观测设计就是在决定：屏幕上的哪些信息、
用什么形式，翻译成这 242 个数字。

一条贯穿始终的原则：**所有跟方向有关的量，都转成"以我的车头为正前方"的坐标系**
（叫**自车系**）。为什么？因为「敌人在我正前方」和「敌人在我正后方」
如果用地图的东南西北来表示，是四种完全不同的数字，网络得分别学四遍。
转成自车系之后它们是同一件事，网络只用学一遍。这叫**利用问题的对称性**，
是白捡的样本效率。

下面逐组说。

---

**① self —— 我自己（10 个数）**

我在地图上的归一化位置（0~1）、我的朝向（拆成 cos 和 sin 两个数，
因为角度 359° 和 1° 其实很近，但数字上差 358，直接给角度网络会学歪）、
我打出去几发子弹了、扳机松没松（这个游戏开火是**边沿触发**，
按住不放只会开一枪）、这帧撞墙没、这帧在贴墙滑行没、我还活着没、
以及**这一回合的格子有多大**。

最后一个容易被忽略但必须给：迷宫尺寸每回合都变（4-12 × 4-10 格），
格子边长跟着变，而**所有速度常量都是按格距缩放的**。
不告诉它这一局的尺度，它就不知道"前进一帧能走多远"。

---

**② enemy —— 对手（9 个数）**

对手在**我的车头系**里的位置、离我多远、它的朝向相对我转了多少、
它剩几发子弹、活着没。

加两个关键的：

- **有没有直线视野**（我和它之间是不是没墙）
- **迷宫路径距离**——绕着走要多远

这两个在迷宫里差别巨大：对手可能直线离我 2 格但要绕 8 格才走得到。
只给直线距离，agent 会以为很近然后一头撞墙。

**注意这里没有的东西**：对手 AI 的内部状态（它当前的目标、动作栈、
攻击性数值）。那些是**特权信息**，部署时拿不到。上个项目的
exact-state teacher 就是栽在这——它能看对手真实 RNG 和内部目标栈，
所以 100% 胜率，但蒸馏进网络后动作一致率只有 22.5%，
因为学生根本看不到老师用来做决定的那些信息。

---

**③ bullets —— 子弹（8 个槽 × 7 个数 = 56）**

按**离我从近到远**排序，取最近的 8 发。每发给：

存在标志、在我车头系里的位置、速度方向（单位向量）、剩余寿命、
以及一个把**归属和反弹状态合在一起**的数：

| 值 | 含义 |
|---|---|
| −1 | 我打的，还没反弹过 → **对我完全无害** |
| 0.5 | 我打的，已经反弹过 → **会杀我** |
| +1 | 对手打的 → 一直会杀我 |

这一个数编码了这游戏最反直觉的规则。给成两个独立的 0/1，
网络得自己学会"这两位组合起来才有意义"；合成一个数是白送的先验。

为什么按距离排序？因为**顺序不该有意义**。如果按创建顺序给，
"槽 0"这个位置有时是威胁有时不是，网络学不出稳定的模式。
按距离排序后，槽 0 永远是"最近的那发"。

---

**④ rays —— 墙距射线（24 个数）**

从我身上向 24 个方向（车头系，每 15°）各发一条探针，
测到第一堵墙有多远，归一化到 0~1。像蝙蝠回声定位。

这是最便宜的"周围地形"表示。**为什么不直接给整张迷宫地图？**
上个项目试过（P18，把地图喂 CNN），**22.5% 惨败**。
教训是「小算力下手工特征 > 学习表征」。射线是手工特征。

---

**⑤ field_patch —— 击杀场的局部窗口（5×5 × 2 层 = 50）**

这个要先解释**击杀密度场**是什么。

正着问「我从这里开枪能打中吗」很贵——每个格子都要模拟一遍。
所以反过来问：**从敌人所在的格子，向四面八方发 512 条射线，
让它们反弹，凡是射线扫过的格子，就是"从那里开枪能打到敌人"的格子。**
一次计算就得到一张"哪里是好射位"的热力图。

两层：
- **场值**：这格有多少条射线扫过（越多 = 越好的射位）
- **引导包络**：把好射位的质量沿迷宫距离扩散开，
  保证**每个可达格都有正值，且沿最短路严格上升**

第二层是导航用的。光有第一层，agent 站在一个场值为 0 的地方
就完全不知道该往哪走（梯度为零）；有了包络，它总能"往上爬"。

只取我周围 **5×5** 的窗口，而且**按我的朝向旋转对齐**。
为什么不给整张？因为迷宫尺寸每回合都变，给整张观测维度就不固定了。

---

**⑥ field_scalars —— 我脚下这格的场摘要（9 个数）**

档位、相对成功率、绝对成功率、引导值、最短飞行帧，
再加一组**最佳瞄准方向**：从这格开枪打中敌人的最好角度是哪个、
我现在的炮口离它差多少（拆成 cos/sin）、这个最优方向有多集中
（是一个窄缝还是一大片都行）。

这组是 MPC 的 alignment 评分项用的东西。给了它，
agent 才谈得上"瞄准"。

---

**⑦ risk —— 有没有子弹要打我（5 个数）**

把每发在飞的子弹当成会反弹的折线往前推 30 帧，
算它离我最近能到多近。输出：

整体威胁紧迫度（0~1，1 = 马上打到我）、最危险那发的最近距离、
它**从哪个方向来**（车头系单位向量）、还有多久到。

只给"有危险"是不够的——**得知道从哪来，才知道往哪躲。**

---

**⑧ round —— 回合状态（6 个数）**

时间进度、结算倒计时（有人死后世界还活 75 帧，在飞的子弹仍能反杀）、
是否已冻结、还剩几个人活着、比分差（已截断到 ±1）、迷宫尺寸。

---

**⑨ action_history —— 我前 4 个决策（4 × 18 = 72）**
**⑩ run_length —— 当前动作连续做了多久（1）**

这两组是**「像人」的关键**，值得单独说。

没有它们，网络在结构上**无法表达"我正在持续做一件事"**。
每一步它看到的都只是当下的世界，于是"继续前进"和"突然倒车"
在它眼里是同等自然的选择——抖动是必然的，不是训练不够。

上个项目冠军模型 40 局里 `stutter_stall`（抖动卡顿）记了 **246 次**，
根因就在这。

---

### 关于「衍生特征算不算作弊」

击杀场、引导包络、风险度、路径距离——这些不是引擎直接给的，
是算出来的。给它们算作弊吗？

**不算。判据是：它是不是"已经可见的东西"的确定性函数。**

击杀场完全由（迷宫布局 + 敌人在哪格）决定，而这两样 agent 本来就看得见。
所以给不给它，**agent 掌握的信息一分不多**——区别只是它要不要自己
从头学会那套反弹几何。

反过来，这些是真作弊，因为它们**扩大了信息集**：

| 禁止 | 为什么 |
|---|---|
| 地图种子 / RNG 状态 | 能推出未来。agent 会背出图，而不是学会打 |
| MPC 对 18 个动作的评分 | 这是"答案"不是"事实"，给了就退化成抄 argmax |
| 对手 AI 的内部目标栈 | 部署时拿不到 → 训练和部署错位 |
| 未来任何一帧 | 同上 |

一句话：**给「关于世界的事实」，不给「关于决策的答案」。**

|---|---|---|
| self | 10 | 归一化位置、朝向 sin/cos、弹药、扳机、撞墙、贴墙、存活、格距 |
| enemy | 9 | 自车系相对位置/距离/相对朝向、弹药、存活、直线视野、迷宫路径距离 |
| bullets | 56 | 8 槽 × (存在、相对位置、速度方向、剩余寿命、归属+反弹状态) |
| rays | 24 | 24 条墙距射线 |
| field_patch | 50 | 5×5 邻域 × (场值 log2、引导包络)，按朝向旋转对齐 |
| field_scalars | 9 | 档位、相对成功率、成功率、引导、最短飞行帧、最佳瞄准角误差、集中度 |
| risk | 5 | incoming risk + 最危险子弹的方向和到达时间 |
| round | 6 | 进度、结算倒计时、冻结、存活数、比分差(已截断)、迷宫尺寸 |
| action_history | 72 | 前 4 个决策的 one-hot |
| run_length | 1 | 当前动作连续段长度 |

**动作 18 个**（3 油门 × 3 转向 × 2 开火），不屏蔽。

传 `field=None` 会把 ⑤⑥ 两组全部归零——这就是观测消融的 `raw-only` 那一臂，
用来回答「信息 > 激励」在这个游戏上到底成不成立。

### obs_check 抓到两个真 bug

写完编码器先跑体检，10500 个样本：

- **比分差无上界**，跨回合累加到了 **−34**。改成 `clamp(diff/5, -1, 1)`
- **射线比例超过 1.0**（1.042）：`ceil(max_range/step)` 在浮点上算成了 25 步而不是 24

两个都是"训完才会发现不对劲"的那种。现在体检报告：无 NaN、无越界、只有第 8 个子弹槽从没填满（正常，10500 样本里没出现过同时 8 发子弹）。

### 我自己引入的一个 bug，以及它带出的一个重要测量

写数据收集器时发现：`COMMIT_MOVE_FRAMES = 4` 是按**引擎帧**算的，
但我每 4 帧才调一次 `act()`，承诺就变成了 **16 帧**。

修法很干净：**frame_skip 本身就是承诺机制**，teacher 在学生节奏上应该每个
决策点都重新规划。把承诺长度从常量改成 agent 的字段，收集时置 0。

顺手把这件事测清楚了（200 局，种子段 900000，512 射线）：

| 配置 | 胜率 | 耗时 |
|---|---|---|
| 每帧决策 + 4帧承诺 | **91.0%** | 24s |
| 每帧决策 + **无承诺** | **91.0%** | 78s |
| 2帧决策 + 无承诺 | 75.5% | 40s |
| **4帧决策 + 无承诺（学生节奏）** | **72.0%** | 19s |
| 4帧决策 + 承诺（=16帧，那个 bug） | 59.0% | 6s |

三个结论：

1. **承诺机制对强度毫无贡献**（91.0% vs 91.0%），它纯粹是防抖动的观赏性装置，
   代价只是慢 3 倍。这是「风格项免费午餐」的又一个数据点
   ——只不过这次是反过来的：**观赏性装置不花钱**。

2. **决策频率的代价是强非线性的**：

   | 决策间隔 | 反应时间 | 胜率 | 相邻差 |
   |---|---|---|---|
   | 1 帧 | 40 ms | 91.0% | — |
   | 2 帧 | 80 ms | 75.5% | **−15.5** |
   | 4 帧 | 160 ms | 72.0% | −3.5 |

   **超人的部分几乎全集中在 40→80ms 这一步。**
   人类反应 200–250ms ≈ 5–6 帧，所以 4 帧（160ms）已经比人略快一点。

3. **归因订正**：我一开始把这 19 个点算在「机会中断」头上，错了。
   `has_fire_opportunity` 只做一件事——把 `commit_remaining` 清零。
   而无承诺时 `commit_remaining` 恒为 0，**中断根本不会触发**。
   所以这纯粹是决策频率，和中断机制无关。
   （这也意味着 `PIPELINE.md` 里 A/B/C 三档中断消融的前提要重写：
   中断只在有承诺时才有意义，而承诺已经被证明对强度无用。）

**BC 学生的天花板是 ~72%，不是 91%。** 后面所有对照都要拿 72% 当参照。

### 数据集格式

Rust 收集器写扁平二进制 + JSON 头，numpy 直接 memmap，没有解析器。
`meta.json` 里带 **观测 schema 版本**，加载时不匹配就拒绝——
上个项目丢过 run 就是因为"同维度不同语义的数据混训"，而失败长得像"效果一般"
而不是像报错。

标签是**整条 18 维评分曲线**，不是 argmax；每个决策步的 18 个候选
**共用一个沙盒种子**（配对比较）；teacher **关掉承诺**按学生节奏决策。
评测指标是 **regret**（选的动作比最优差多少，按该样本的评分跨度归一化），
不是 top-1 命中率。

### BC 训练器

`training/bc.py`。要防的是 killfield 那次的失败模式：
**BC 后策略熵只有 0.57，零探索，扔进没见过的状态直接崩。**

对策：软标签（温度 0.05 的 softmax over 归一化评分）+ label smoothing 0.02
+ 最后一层小初始化（gain 0.01）。每个 epoch 报熵，坍缩了立刻看得见。

网络：242 → 256 → 256 → {18 policy logits, 18 辅助评分回归}。
辅助头不参与推理，它的作用是把"好多少"这个信息也用上，塑形躯干的特征。

冒烟测试（1129 样本，当然学不动）：regret 0.25，
参照 teacher 0.0008 / 随机 0.72，**熵稳在 2.27（均匀 2.89），没坍缩**。

正在采 2000 局的正式数据集（种子段 100000，和三个评测种子段都不重叠）。

### 正式数据集

```
data/bc_v1   111,212 样本 / 1997 回合 / 113 MB / 197 秒采完
             种子段 100000，和三个评测种子段都不重叠
             teacher 1421胜 / 421负 / 155双杀 = 71.2%
```

否则一个终局击杀（±12000）会把整批的梯度带跑。

## 2026-08-21 — O/A/R 冻结、Laika 与 MPC 蒸馏、DAgger 闭环验证

### 今天真正决定了什么

昨天的 242 维表是探索草案，今天经过逐项讨论后被正式替换。当前唯一有效设计以
`docs/DESIGN.md` 为准：**1057 维语义观测、18 个动作、逐帧 25Hz 决策**。

观测原则也从“尽量压缩”改成了“人类能从完整画面知道的事实都可以给，但不能直接给决策
答案”。因此给模型完整迷宫拓扑和等长最短路径区域，而不是只给局部墙；给每颗子弹的相对
位置、速度矢量、归属和是否反弹；不给精确寿命、刚创建标志和未来轨迹。对手部分给当前
相对位姿、弹槽、存活和路径长度；危险感、击杀场和射击质量不直接进入观测，留给记忆和
训练信号学习。

当前 1057 维为：

| 组 | 维度 |
|---|---:|
| 全局迷宫 `12×10×8` | 960 |
| 双方最短路径长度 | 1 |
| 自身坦克 | 9 |
| 对手坦克 | 6 |
| 全部子弹，最多 10 发 × 6 | 60 |
| 回合阶段 | 3 |
| 上一次动作 | 18 |
| **合计** | **1057** |

子弹槽用共享编码器后做与排列顺序无关的汇总，补空槽另有遮罩。循环模型仍得到上一次动作，
因为有记忆不等于要删掉人类本来就能感知的自身操作。

动作仍是 `3 油门 × 3 转向 × 2 开火 = 18`。教师频率探针证明 160ms 保持动作会先把
Laika 的战力从约 40.5% 破坏到 19.6%，所以 BC、DAgger 和之后 PPO 全部统一为每 40ms
决策一次，新回合清空记忆。

### Reward 第一版和实时调参页

把已经讨论清楚的奖励机制写进 Rust，并接到网页逐通道账本。当前结构是：终局、零和交战
主动权、击杀场单调推进、纯击杀质量、例无虚发、精准制导、刀口舔血、正太扭腰，以及连续
无效撞墙。取消追猎金币、等待惩罚和简单按键反向惩罚；等待本身不扣分，前后/左右反复是否
有害由击杀场推进是否保留下来判断。

击杀类奖励不只在命中一帧支付：命中时支付一部分，剩余部分在击杀后存活到结算的窗口内
后重前轻地支付。准备击杀之前的动作，使用击杀场势能创下新高的时刻做反向归因，避免前进、
后退、再前进重复刷分。正太扭腰改成反事实定义：同一危险状态下 Laika 会被现有敌弹击中，
模型实际没有死，才算有效闪避。

网页加入 Reward 参数面板、每帧/每局/累计账本、曲线和成就事件。调参数只重置奖励账本，
不重开对局，也不改变正在观察的 Killfield/Laika 控制器。

### 五个固定模型

所有模仿实验都使用相同 O/A，只改变记忆结构：

| 名称 | 结构 |
|---|---|
| 无记忆 | 当前观测 + 上一次动作，普通网络 |
| 四步 | 最近四帧直接堆叠，普通网络 |
| GRU | 当前观测逐帧输入通用循环记忆 |
| 预测 | GRU，另加训练时对手未来位置/朝向考试 |
| 分离 | 地图、当前物理、对手记忆、自身控制记忆分开 |

另外加入训练时瞄准考试，用于检查编码器是否理解“此刻开枪会发生什么”；答案不进入策略
观测，部署时也不存在，所以没有改变当前 O。

### Laika BC 与四轮 DAgger：离线好看，闭环失败

基础逐帧数据为 400 局、184,979 个状态。基础数据上单步动作准确率约 81%–84%，但五个
模型对 Laika 的闭环胜率只有 5.4%–7.2%。随后做四轮 DAgger，累计 390,220 个状态，
最后把循环记忆延长到 128 帧（5.12 秒），最好仍只有 7.4%。

DAgger 的工作方式是让学生自己行动，再让教师给学生实际走到的状态补标签。它没有救回
Laika 蒸馏的主要原因不是“没覆盖学生状态”，而是 Laika 标签依赖自己不可见的目标、路线和
动作栈；学生没有执行教师原计划时，同一个可见状态会收到受隐藏计划影响的动作标签。

这组实验因此**没有证明观测有效**，也不能直接证明观测无效。它证明的是普通行为克隆和
普通 DAgger 无法从这个带隐藏计划的教师得到可靠闭环策略。详细数字在
`experiments/bc_laika/RESULTS.md`。

### MPC 评分蒸馏与两轮 DAgger

回看旧 `tank_trouble` 项目后确认，过去能模仿 MPC 的关键不是硬动作标签，而是学习完整
候选动作评分地形；旧观测还包含精确子弹寿命、射击扇未来结果和九种移动的短期动作后果。
今天的新实验保留“完整评分地形”方法，但严格使用当前 1057 维 O，不把那些旧特权补回来。

Rust FFI 为每个状态输出 18 个配对候选评分和有效动作遮罩。DAgger 时学生真实执行动作，
MPC 的撞墙、追猎链和上一动作效果记忆也跟随学生动作更新，然后才重新评分，避免教师历史
与世界历史错位。采集和模型断点均原子写入，可以在合盖或中断后续跑。

正式数据：

| 阶段 | 新样本 | 累计样本 |
|---|---:|---:|
| MPC 基础轨迹，400 局 | 117,095 | 117,095 |
| DAgger 第 1 轮，五模型各 80 局 | 66,195 | 183,290 |
| DAgger 第 2 轮，五模型各 80 局 | 61,726 | 245,016 |

基础教师 400 局为 367 胜、22 负、11 双亡，即 **91.75%**。学生闭环结果：

| 模型 | 基础 BC | DAgger 1 | DAgger 2 |
|---|---:|---:|---:|
| 无记忆 | 8.0% | 8.7% | 5.2% |
| 四步 | 11.5% | 7.3% | 7.2% |
| GRU | 7.5% | 7.0% | 6.8% |
| 预测 | 10.5% | 7.7% | **7.4%** |
| 分离 | 7.0% | 5.3% | 6.4% |

DAgger 暴露了强烈分布偏移，但没有把策略拉回教师分布。聚合测试集中 MPC 选择开火只占
2.84%；学生对这些关键状态的识别率只有 11%–20%。额外做了开火重权负对照：识别率升到
约一半，但精确率只有约 7%，大量错误开火使胜率进一步降到 4.7%。所以失败不只是类别比例
失衡。

这次结果否定的是“现有小网络 + 当前 1057 维 O + 普通评分蒸馏 + 两轮 DAgger 可以可靠
复现 MPC”。它还不能证明这组观测在无限容量下数学上不充分。下一项最干净的实验应在两者
中只选一个：保持 O 不变，换更强的空间网络并做辅助重建；或者明确新增“动作条件短期物理
预演”作为观测消融，检验缺的是不是旧项目那组动作后果信息。详细报告在
`experiments/bc_mpc/RESULTS.md`。

### 时间与基础设施

本次 MPC 正式流程在 M5 上约 63 分钟：模型训练约 42 分钟，MPC 采集约 4.4 分钟，三阶段

## 2026-08-21（续）— 冻结 O/A，启动最小奖励 PPO R1

正式冻结 schema 2 的 1057 维 O 和 18 动作 A，不再因为 BC/MPC 蒸馏失败而临时补特权
观测。策略编码固定为：迷宫小 CNN、子弹共享 entity encoder + mean/max masked pooling、其余
scalar MLP。PPO 第一阶段只比较无记忆和 GRU-256，不再同时铺五种结构。

先用 64 个固定 Laika 环境采 131,072 个逐帧样本做范围体检：无 NaN/Inf，地图/阶段/动作
的 binary/one-hot、子弹 mask/padding、位置和速度范围全部通过。唯一告警是路径标量经验最大
1.1364；编码除以 22，而迷宫绕路可以超过 22 格，理论上界 5.4091。因为 O 已冻结，不裁剪
也不改除数，把它记录为“有界但非单位区间”。

R1 reward 只启用 terminal、零和势函数 initiative、repeated-wall。从 160ms 改到 40ms 后，
势函数 gamma 从 0.99 改为 0.9975；RewardTracker 为 R1 每帧更新，网页实验室仍保留原四帧
采样。style、kill quality、三个击杀成就和 dodge 六个通道逐值验证为零，counterfactual
dodge 分支不会运行。FFI 直接输出九个 reward channel 和双方势能诊断，训练端不从总奖励
猜分量。

PPO 固定 64 env × 256 rollout、4 epochs、1024-step minibatch、lr 3e-4、clip 0.2、
gamma 0.9975、GAE lambda 0.95、entropy coefficient 0.01；训练种子 11/22/33，对手固定
Laika，评估种子段固定 2,100,000。GRU 使用连续 64 帧 truncated BPTT，rollout 保存每段
起始 hidden，episode reset 清零；连续分块与 reset 等价测试通过。

R1 gate 在看正式结果前固定：每个架构三个种子都要达到主动权提升回合 ≥35%、进入四格内
回合 ≥30%、主动开火回合 ≥30%，并保持关闭通道为零；至少一个架构通过才允许加下一条
reward。胜率只记录，不作为 R1 门槛。两个模型的 32,768 步端到端冒烟通过，正式
`2 models × 3 seeds × 5M steps` 已用 caffeinate 启动并逐 update 原子保存。

## 2026-08-22 — PPO R1 正式门控通过

完成无记忆和 GRU-256 各 3 个独立种子、每组 5,013,504 环境步，共 30,081,024 步。正式
评估每组使用固定的 256 回合 Laika 对手。三个无记忆种子的主动推进/近距接触/开火率为：

| 种子 | 主动推进 | 近距接触 | 开火 | 胜率 |
|---:|---:|---:|---:|---:|
| 11 | 0.766 | 0.848 | 0.879 | 0.027 |
| 22 | 0.816 | 0.855 | 0.895 | 0.043 |
| 33 | 0.793 | 0.887 | 0.766 | 0.070 |

三个 GRU-256 种子为：

| 种子 | 主动推进 | 近距接触 | 开火 | 胜率 |
|---:|---:|---:|---:|---:|
| 11 | 0.805 | 0.801 | 0.949 | 0.051 |
| 22 | 0.730 | 0.816 | 0.926 | 0.086 |
| 33 | 0.809 | 0.879 | 0.930 | 0.062 |

两个架构均为 3/3 种子通过预注册门槛；style、kill quality、例无虚发、精准制导、
刀口舔血和 dodge 在所有最终评估中严格为零，且没有超时回合。因此 O/R/episode reset/PPO
没有触发 R1 的 fail-closed 排查规则，可以进入一次只增加一个通道的累计消融。

本轮 MPS 实际耗时约 2.51 小时：无记忆三组共 49.8 分钟，GRU 三组共 100.5 分钟；GRU
连续 64 步 BPTT 的平均吞吐约 2,385 steps/s，无记忆约 5,695 steps/s。全部最终模型、逐更新
指标、断点和 `GATE.json` 位于 `outputs/ppo_r1/`。

结论边界：R1 已证明“会主动进入交战”，没有证明“会打赢”或“射击合理”。最终胜率只有
2.7%–8.6%，GRU 三个种子的回合开火率都超过 92%，需要用观战检查高开火是否包含无意义
耗弹。下一阶段不得同时打开多个奖励，也不在尚未冻结通道顺序和权重时启动 R2。
