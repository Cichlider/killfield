## 2026-09-30 — 手机默认改为八向扇区摇杆

### 动机

世界轮盘把「往哪儿走」交给玩家，坦克自己转过去对准，所以手机上不需要任何转向时机；
键盘玩家却要自己算转速和提前量。同一个游戏里两套手感的强度差得太远。

新方案把键盘的问题原样搬到触屏上：**现在按住哪些方向键**。它因此没有任何键盘到不了的
转向速率，也不需要再靠「瞬间转向」这种补偿来找平。

### 实现

- 新增「触屏操控」选项，两项：`方向键（八向）`（默认）与 `轮盘（128 方向）`。选择保存在
  浏览器本地（`killfield-touch-scheme-v1`）；旧浏览器没有这个 key，因此直接拿到新默认。
- 八向摇杆把圆盘按角度切成八个扇区，每个扇区就是一组方向键：

  | 扇区 | 指令 | 扇区 | 指令 |
  |---|---|---|---|
  | 上 | 前进 | 下 | 后退 |
  | 左 | 左转（原地） | 右 | 右转（原地） |
  | 左上 | 前进 + 左转 | 右上 | 前进 + 右转 |
  | 左下 | 后退 + 左转 | 右下 | 后退 + 右转 |

- 半径分三段：中心区静止，过渡区把强度从 `0` 线性加速到 `1`，满速区输出 `1`——因此推到
  满速区时与键盘满按逐位相同。`padCell()` 返回的仍是
  `forward/backup/turnLeft/turnRight`，到 FFI 之前和键盘完全同构，物理、预测和排位录像
  都不需要知道是哪种控件。
- 扇区边界有黏滞（默认 `6°`，并按扇区宽度收缩）：手指停在分界线上时保持当前扇区，不会
  每帧在「前进」和「前进+右转」之间抖动。
- 选中八向时，只属于轮盘的「瞬间转向」与「轮盘区域规划」置灰禁用；切回轮盘即恢复。
- 触控层的外观沿用原设计：左侧移动、右侧开火、可隐藏、横屏/全屏不变。

### 手感配置

八向摇杆的每个手感数字都可以在页面里调整，选择存在浏览器本地
（`killfield-pad-tune-v1`），并且可以整份导出/导入 JSON：

- **圆形**：中心区占比 `0–60%`、过渡区占比 `0–80%`（`0` = 一出死区即满速），以及
  右半边的四条分界线角度（前进锥 / 前对角 / 原地转向 / 后退锥）。左半边是它们的镜像，
  所以前后可以不同、左右永远对称。
- **方形**：`3 × 3` 九宫格，默认九等分、**没有过渡区**；参数是三条网格线（边列宽度、
  上行高度、下行边界），左右同样镜像。
- **摇杆大小** `96–240px`：实际尺寸仍受视口上限约束，不会盖住迷宫。

每个参数**就是一条分界线**，所以控件之间互不干扰：拖一条线只会改变它两侧的扇区宽度，
其它线不会跟着缩放；需要越界时只把被拖的那条线夹在邻线旁边（`setPadTuneField()`）。
面板滑杆由 `viewer/src/pad.js` 的 `PAD_TUNE_FIELDS` 生成，界面、模型和导出的 JSON 不会
各自漂移；导出/导入共用同一段 JSON，缺字段补默认、越界值夹取并吸附到滑杆步长。

### 三指按键

「触屏操控」多了第三种方案 `三指按键 / Three-finger pads`：左手一组前进/后退，右手一组
左转/右转，开火键独立；按键是数字的（按住 = 1），和键盘完全等价。**两组按键完全独立**：
各自的位置（`%`）、按键大小（`40–120px`）、组内两颗键的间距（`0–48px`），再加开火键的
位置与大小；默认 `22%/74%`、`78%/74%` 各 64px、间距 8px、开火 `78%/38%` 88px——开火键
高度特意取 38%，避开画布右上角的工具条。调整模式下每组按键左上角有一枚手柄，拖动即整体
移动（只改这一组），手柄的 `pointerdown` 不会穿透到按键。

### 直接拖分界线

打开「手感设置」面板即进入调整模式：摇杆固定到视口上方（`body.tuning`），并在每条可调的
分界线上立一枚手柄（`padPins()`），直接拖动即可改变该分界线；面板里的滑杆同步跟随。方形
模式的手柄在网格线上，圆形模式的在角度分界线上。手柄的 `pointerdown` 会
`stopPropagation()`，所以拖手柄不会同时驱动坦克；面板里另有「隐藏/显示摇杆」，与画布上的
`CTRL` 是同一个开关。

### 高亮只有自己按到的那一格

按半径分三区（中心 / 过渡 / 满速，方形无过渡）、按方向分八个，圆盘上是 `8 × 3 = 24` 格、
方盘上是 `3 × 3 = 9` 格。按住时**只亮当前这一格**：格子内部填色、该方向的边缘发光；中心
区没有方向，就只填这一块。换手感（含拖手柄）时，手指不离盘也会按新几何重新解析当前格子，
不会出现画面落在手指后面的错位。

### 拖动与显示的三处修正

- **手柄/圆点拖动不再瞬移**：按住手柄或分界线圆点时先记下手指与控件中心的偏移，之后按
  「控件中心 = 手指 − 偏移」换算，所以控件跟着手指走而不是跳到手指下面。
- **拖动不再只动一下**：手柄每帧重绘会让浏览器丢掉 pointer capture，拖动在第一个事件之后
  就失效。现在 `renderPins()` 只在手柄集合变化时重建，其余情况原地改 `left/top`，分界线
  圆点和方形网格线都能一路跟手（回归测试里拖出一条 100→105→95→90→85 的轨迹）。
- **调整针不再挤在一起**：相邻分界线的手柄交错放在两个半径上（`0.84` / `0.46`），方形模式
  的两条平行网格线的手柄也沿各自网格线错开；手柄直径随摇杆大小缩放（`14–26px`），所以
  竖屏、窄扇区（比如把前进锥收到 2.5°）都不会糊成一团——实测默认八枚手柄最近间距 44px，
  收到 2.5° 时仍有 28px，而手柄只有 22px。
- **调整模式与游戏内的观感一致**：摇杆尺寸、比例、旋钮完全相同，调整模式下因为浮在页面
  上而补了一层更实的底与阴影，避免看起来像另一个控件。
- **全屏下不再串台**：全屏人机布局为了左栏给 `.touch-left-control` 设了 `display: flex`，
  它的优先级高于「三指方案隐藏八向摇杆」的规则，所以在全屏里开三指会同时看到（可能还是
  方形形状的）摇杆。该隐藏规则现在带 `!important`，窗口与全屏都只显示三指按键。

### 回归检查

新增 `node viewer/tests/pad.test.mjs`，覆盖八向与键盘的等价、三种径向分区、分界线顺序与

## 2026-08-24 — Main 版本收尾

### 仓库与定位

- 项目收敛为 Killfield：一个 Tank Trouble 风格迷宫坦克游戏和实时 MPC 智能体。
- `engine/` 是唯一权威游戏实现；本地程序和网页均使用同一 Rust crate。
- `viewer/` 是 GitHub Page 和本地观看/对战入口；保留 MIT License。
- `main` 暂停 PPO 路线。后续 PPO 从独立 branch 开始，避免训练试验污染可运行的 MPC 版本。

### Rust 引擎与 MPC

- 游戏固定以 `25Hz / 40ms` 推进，包含迷宫、坦克运动、贴墙滑动、碰撞、反弹子弹和终局结算。
- 击杀后世界继续运行三秒，在途子弹仍可能把胜利改成双杀。
- Killfield 使用反向弹道密度场寻找射位，再在隔离沙盒中推演 18 个移动/转向/开火组合。
- 常规前视为 36 帧；通常最多承诺动作 4 帧，转向和关键事件会提前触发重规划。
- 普通轨迹按射位、guidance、瞄准、位移、弹药、风险和撞墙情况评分；出现终局时终局优先。
- 使用同一固定 Laika 和同一种子段 `20260814–20262813`，每档运行 2000 局：

  | Rays | 胜 | 负 | 双杀 | 超时 | 胜率 | 场重建均值 |
  |---:|---:|---:|---:|---:|---:|---:|
  | **512** | **1771** | 125 | 104 | 0 | **88.5%** | 0.607 ms |
  | 1024 | 1767 | 123 | 109 | 1 | 88.3% | 1.017 ms |
  | 2048 | 1767 | 132 | 100 | 1 | 88.3% | 1.686 ms |

- 512 rays 按种子顺序的最大零封为 `63` 连胜；双杀/平局保持当前连胜但不增加，失败清零。
- 另用不重叠种子段 `20262814–20264813` 复测 2000 局：`1774` 胜、`122` 负、`103`
  双杀、`1` 超时，胜率 `88.7%`，最大零封 `68` 连胜。README 采用这批新结果。
- 三组并行运行，墙钟时间和最大规划延迟受 CPU 争用影响，不作为单任务性能基准。固定种子下
  1024/2048 没有提高胜率，而场重建更贵，因此 Page 继续以 512 rays 作为最高默认精度。

### Web Viewer

- Rust 引擎编译为 `viewer/kf_engine.wasm`；网页不保留第二套 JS 物理。
- Page 提供三种模式：Killfield vs Laika、Human vs Killfield、Killfield 自对弈。
- 页面提供 512/256 rays、随机种子、对手模型、MPC telemetry 和可实时调整的参数面板。
- 记分板记录当前比分、连胜和本机历史最佳连胜。
- README 重写为当前项目说明，并使用 GitHub 可渲染的数学公式介绍 score 与终局优先规则。

### 人类控制

- 键盘移动、转向和开火直接读取当前按键集合，不累计按下时长，也不重放已经松开的输入。
- 手机支持横屏、全屏、隐藏触控层、左侧移动摇杆和右侧开火键。
- 左侧摇杆当时只有世界轮盘一种方案：128 个世界方向，每档 `2.8125°`；转向与前进/后退
  可以同时发生。2026-09-30 起默认改为八向扇区摇杆，轮盘退居为可选项。
- 轮盘当前默认 `360°` 前向区（不后退）；用户可在 `0–360°` 间调整，非 `360°` 时扇区外
  的正后方成为后退区。
- 轮盘半径前 `10%` 平滑提高转速，超过后保持最大转速；移动从 `25%` 半径开始，在 `33%`
  达到最大速度。八向摇杆则用 hub 死区 + 半径线性映射，rim 处等于键盘满按。
- Human vs Killfield 提供“瞬间转向”开关，以及 `0–3s` 的 Killfield 开局停顿设置；默认
  `0.5s`，只暂停 AI，人类和世界立即运行。

### 操作延迟与画面

- 世界、AI和子弹保持 25Hz 权威物理；Canvas 按显示器刷新率绘制，DPR 上限为 2。
- 人类坦克不再显示落后一帧的插值。每个显示帧由 WASM 轻量沙盒调用真实墙体/贴墙求解器，
  从当前权威姿态向下一姿态预测，因此不会先画进墙再回弹。
- 人类模式每个显示帧最多补算一个物理帧；卡顿后丢弃过期时间债，不连续重放多次 MPC。
- 手机摇杆同时监听 `pointermove` 和更及时的 `pointerrawupdate`。
- 人类开火在按下沿立即进入权威引擎并播放声音；子弹立即出现、下一物理帧开始移动。
  按住开火、键盘多个开火键或触屏与键盘同时使用都不会重复触发。

### 手机展示

- 全屏横屏布局把记分板放在左侧栏、功能按钮放在右上区域，避免遮挡主要游戏画面。
- 摇杆和开火键使用适合横屏触控的固定可用尺寸；删除了无效的按钮尺寸调节选项。
- 八向摇杆的扇区、同心圆与方向图标是 `viewer/index.html` 里的静态 SVG，只有圆盘带
  `.sectors` 时才显示，因此同一个元素同时服务两种方案。
- 支持标准 Fullscreen API、iOS 回退布局、横屏锁定尝试和无法锁定时的旋转提示。
- 移动端默认使用 256 rays 减少主线程压力，用户仍可切换到 512 rays。

## 本地启动

```sh
rustup target add wasm32-unknown-unknown
bash viewer/serve.sh
```

浏览器打开 <http://127.0.0.1:8000>。端口占用时使用：

```sh
PORT=8001 bash viewer/serve.sh
```
