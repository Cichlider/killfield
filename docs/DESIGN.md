# duel-v1：O / A / R 的完整定义

> 更新于 2026-09-03，对应 `engine/src/duel.rs` 与 `engine/src/duel_obs.rs`。
> 这份文件是定义，不是历史。之前四轮课程（static-target、walking、pursuit、
> hunt、shooting-range）的 O/A/R 全部退役，`docs/LESSONS.md` 保留了它们证伪的
> 结论，代码不再保留它们的观测与奖励。

## 0. 一页总览

| 部分 | 定义 |
|---|---|
| 场景 | 真实 Killfield 对战，每局由 `setup_battle` 随机生成 4-12 × 4-10 迷宫 |
| O | `1010` 维语义数值，schema 20 |
| A | 单一 `Discrete(18)`：`[throttle, turn, fire]`，引擎自身转速，每帧一决策 |
| R | 只在终局结算一次：胜负 + 时间折扣 + 动作平滑分 |
| 对手 | 池化抽取：Laika 40% / MPC 40% / 冻结的自我 checkpoint 20% |
| 终局 | `Event::RoundEnd`，30 秒（750 帧）未分胜负判平 |

设计立场：**不再设计逐帧塑形。** 前四轮每一轮都把游戏换成一个代理任务，再把设计
预算花在那个代理需要的塑形项上，每一轮都被下一个 credit assignment 问题推翻。
这一版把代理去掉，预算转移到观测——这也是仓库自己的第一教训（「信息 > 激励」）。

## 1. O：观测（schema 20，1010 维）

原则：**给关于世界的事实，不给关于决策的答案。** 所有方向量转到以自身车头为
`+x`、左侧为 `+y` 的坐标系。全通道有界在 `[-1, 1]`，有测试守着。

偏移量以 `engine/src/duel_obs.rs` 文件头的常量为准，下表与之对应。

| 组 | 偏移 | 维度 | 内容 |
|---|---:|---:|---|
| 迷宫栅格 | 0 | 840 | 补齐到 12×10，每格 7 个二值通道 |
| 墙射线 | 840 | 16 | 绕车体 16 向到第一堵墙，上限 4 格 |
| 自身 | 856 | 12 | 见 1.2 |
| 对手 | 868 | 12 | 见 1.3 |
| 导航 | 880 | 10 | 见 1.4 |
| 我方瞄准辅助 | 890 | 5 | 见 1.5 |
| 对手瞄准辅助 | 895 | 5 | 同上，站在对手炮口 |
| 子弹 | 900 | 100 | 10 发 × 10 维，见 1.6 |
| 威胁 | 1000 | 3 | 双方 `incoming_risk`、最近子弹的反射最近接近距离 |
| 回合阶段 | 1003 | 4 | 正常交战 / 结算窗口 / 冻结 / 时钟 |
| 上一动作 | 1007 | 3 | `[throttle/2, turn/2, fire]` |

外加 10 位 bullet mask 作为批处理元数据，不算语义维度。

### 1.1 迷宫栅格：`12 × 10 × 7 = 840`

生成器最大产出 12×10，所以这个尺寸覆盖全部情况，小图用有效位补齐。每格 7 通道：

1. 该格有效（padding 为 0）
2. 上墙 `!h_open(x, y-1)`
3. 右墙 `!v_open(x+1, y)`
4. 下墙 `!h_open(x, y)`
5. 左墙 `!v_open(x, y)`
6. 我在此格
7. 敌在此格（且存活）

靶场课程曾因为「P18 CNN 地图头 22.5%」把整张图换成 8 条射线。这里换回来，是因为
奖励也换了：稀疏胜负下没有塑形项在传递信息，信息必须在观测里；而且迷宫每局都变，
不给布局就只能靠射线摸。

### 1.2 自身：12 维

| 维度 | 内容 |
|---:|---|
| 2 | 位置 `x/宽`、`y/高` |
| 2 | 朝向 `cos, sin` |
| 2 | 速度矢量（前 / 左），按上一帧位姿差分 |
| 1 | 角速度 `/ TANK_TURN_SPEED` |
| 1 | 空闲弹槽 `/ 5` |
| 1 | 当前能否开火 |
| 1 | 存活 |
| 1 | `hit_something` |
| 1 | `wall_sliding` |

后两位加上速度和「上一动作的油门档」，让「我在按前进但没动」成为单帧可判的卡死
特征。观测里没有「已经卡了多少帧」，因为没有记忆结构；但当下是否卡着看得见。

### 1.3 对手：12 维

与 1.2 逐项对应，全部转到我车坐标系：相对位置、**相对朝向 `cos/sin`**、相对速度、
角速度、空闲弹槽、能否开火、存活、`hit_something`、`wall_sliding`。

相对朝向是靶场观测里完全缺席的一项——「他的炮口是不是对着我」以前根本看不见。

### 1.4 导航：10 维

| 维度 | 内容 |
|---:|---|
| 1 | `BFS(我 → 敌)` 格数 `/ 60`，不可达为 1 |
| 4 | BFS 梯度方向 one-hot，折进我车坐标系的前/左/后/右 |
| 1 | 直线距离 `/(宽+高)` |
| 2 | 方位单位向量（前 / 左） |
| 1 | 我这格的死胡同惩罚 `/ MAXDEADENDPENALTY` |
| 1 | 他那格的死胡同惩罚 |

BFS 梯度是「关于迷宫的事实」，不是「这一帧该做什么」的建议：它只回答哪个相邻格
更近，不涉及子弹、火力或时机。

### 1.5 瞄准辅助：每侧 5 维

`ballistics::check_bullet_path` 用**当前**炮口角度模拟完整反弹轨迹：

`[命中敌, 命中自己, 谁也打不到, 命中耗时/BULLETLIFETIME, 最近通过距离/(W+H)]`

双方各一份。它假设坦克不动——几何是精确的，近似的是目标可以躲开。

### 1.6 子弹：每发 10 维，最多 10 发

双方各持 5 发，所以 10 个槽位是**足量而非截断**。

| 维度 | 内容 |
|---:|---|
| 2 | 我车坐标系下的相对位置 |
| 2 | 相对速度 |
| 1 | 归属：我的 / 他的 |
| 1 | 是否已反弹 |
| 1 | 剩余寿命 `/ 250` |
| 1 | 弹道预演：会打到我 |
| 1 | 弹道预演：会打到他 |
| 1 | 预演命中我的剩余帧数 `/ 75`（打不到则为 1） |

预演用 `risk::reflective_closest` 前视 75 帧、最多 2 次反弹。子弹只和墙交互，所以
飞行几何是确定的。**我方未反弹的子弹对我无害**——这是引擎的实际规则，不是近似。

槽位顺序是引擎创建顺序，会随发射和过期漂移，所以这 10 行必须过共享编码器 + 带掩码
池化，不能直接接全连接。

### 1.7 明确不进入观测

| 不给 | 在代码里是什么 | 为什么 |
|---|---|---|
| 地图 seed / RNG 状态 | `game.seed`、`game.rng.state` | 部署时不可用 |
| Laika 内部目标栈 | `laika::Goal`、`ai.my_actions` | 对手内部状态，换对手即失效 |
| 对手当前按键 | `tanks[1].forward/…/fire` | MPC 的 `OppModel::L1` 确实读它，但那是同帧特权读取；人眼只能看到位移，所以给速度和角速度 |
| 炮口角度扫描 | `check_bullet_path` 接受任意角度 | 扫 36 格等于直接给「最佳射角」。只给当前角度，找射位必须靠转身学 |
| kill field / MPC 评分 | `field::DensityField`、`score::density_rollout`、`post_kill_survival_scores`、`best_aim_at` | 把搜索的输出当输入 |

前三项由回归测试 `the_opponents_internal_state_never_reaches_the_observation`
守着：固定双方位姿与子弹，打乱 RNG、Laika 的 goal 栈和对手全部五个按键，断言观测
逐元素完全不变。

## 2. A：动作（`Discrete(18)`）

`score::CANDIDATES` 的 `[throttle, turn, fire]`，与 MPC 规划器同一套候选集：

```
throttle  0 倒车 / 1 不动 / 2 前进
turn      0 左转 / 1 不转 / 2 右转
fire      0 / 1
index = throttle * 6 + turn * 2 + fire
```

- **用引擎自身转速**（10°/帧），`*_amount` 覆盖全部留 `None`。瞄准靠多帧转身完成。
- **每帧一决策**，25 Hz，无动作承诺、无帧跳。对比 MPC：它每帧写按键，但搜索有
  承诺窗口（`COMMIT_MOVE_FRAMES = 4`、`COMMIT_TURN_FRAMES = 2`）。
- **有显式倒车挡**。
- MPC 实际只在 18 个里的 10 个中选（`mask_moving_fire_scores` 把 8 个「边走边打」
  压成 `-1e9`）。`score.rs` 的注释明说 RL 动作空间**刻意不继承**这个 mask，
  所以我方策略比 MPC 对手多 8 个合法动作。

## 3. R：奖励

**全程 0，只在终局结算一次。** 定义在 `engine/src/duel.rs`。

### 3.1 终局值

| 结果 | 值 |
|---|---|
| 赢 | ≤10 秒 `+1.0`；10→30 秒对数衰减到 `+0.5` |
| 双亡 | `0.0` |
| 输 | `-1.0` |
| 30 秒平局 | `-1.0` |

**时间折扣**（`win_reward`）：

```
frames ≤ 250          →  1.0
250 < frames ≤ 750    →  1.0 − 0.5 · ln(frames/250) / ln(3)
```

对数而不是线性，因为形状本身在说话：第 11 秒值 0.083，第 29 秒值 0.017。一局已经
拖长之后再拖几乎免费，所以压力落在还能改变决策的地方。结算窗口的溢出帧夹到 750，
所以 0.5 是真正的地板。

| 秒 | ≤10 | 12 | 15 | 20 | 25 | 30 |
|---|---:|---:|---:|---:|---:|---:|
| 奖励 | 1.000 | 0.917 | 0.815 | 0.685 | 0.583 | 0.500 |

**平局与输同价。** 不接战就会被时钟判 −1，和被打死一样贵。这条堵掉了历史上纯胜负
`±1` 学出「苟活不开火」（12.4%）的那个退化解——它当时没有时限，苟活是严格最优。

**双亡为零。** 曾经给过 `+0.2`，理由是「还不会赢的策略需要为贴上去、扣扳机拿到
钱」。但那个压力已经在尺度的另一端了，两头都给等于花钱买换命——当时自我对战里
60.3% 的对局以换命收场。

### 3.2 动作平滑分

叠加在任意终局上，上限 `STYLE_MAX = 0.25`：

```
rate = 动作变更数 / (帧数 − 1)
rate ≤ 0.13  →  0.25
rate > 0.13  →  0.25 · (1 − ln(rate/0.13) / ln(1/0.13))，下限 0
```

**满分线 0.13 是实测的**：`engine/src/bin/probe_actions.rs` 跑 200 局，Laika 是
12.9%、MPC 是 12.7%，两者折算成同一个三元组。两个打得好的控制器落在同一条水位线
上，那就是「像个称职玩家那样改主意」的价格。低于它没有额外收益——一个从不换动作
的控制器不是在反应。

**用频率不用次数**，这一条是承重的：按次数记分、以一局约 294 帧校准阈值的话，任何
早早结束的一局都白拿满分，而最省事的结束方式是去死——何况时间折扣本来就已经在
为短局付钱。频率与长度无关，有测试把 31 帧和 301 帧的同一行为钉在同一个分数上。

### 3.3 数值约束（有测试守着，改常数前先看）

加了平滑分之后，要维持 `平 = 输 < 双亡 < 胜`：

```
WIN_FLOOR   > 双亡 + STYLE_MAX     最差的胜必须赢过最好看的双亡
REWARD_WIN  > WIN_FLOOR + STYLE_MAX 快而糙的胜必须赢过慢而美的胜
双亡        > 输 + STYLE_MAX        最差的双亡必须赢过最好看的负
```

第一条给出 `STYLE_MAX < 0.5`：在恰好 0.5 时，一个动作完美的双亡等于一个拖满 30 秒
的胜利。取 0.25 在三条上各留 0.25 的余量。

换命的盈亏平衡点是 `(双亡 − 输)/(胜 − 输)`，随时钟移动：回合初 50%，回合末 67%。
测试断言它落在 45%–90%。

### 3.4 终局判定

**只认 `Event::RoundEnd`。** `destroy_tank` 把 `end_count` 置 125，`step()` 逐帧
递减，到 50 时才 `frozen = true` 并推送 `RoundEnd`——也就是首次击杀的 **75 帧之后**
（`SETTLEMENT_FRAMES`），其间在途子弹仍然致命、仍可能把胜利改成双亡，而第二次死亡
会把计数器重新拉到 125 再延一轮。

两条边界：

- 不能在 `Event::Destroy` 或 `alive_count <= 1` 上提前终止，那样会吃掉结算窗口里
  的翻盘（`LESSONS.md`：「v2 学出同归于尽，修复方式是把终局判定改回去对齐真实
  计分规则」）。
- 也不能跑过头：`RoundEnd` 之后 55 帧 `setup_battle()` 会在 `step()` 内部就地重开
  一张新迷宫，观测会无声跳到另一个竞技场。兜底再判一次 `round_number`。

## 4. 对手池

每局每槽独立掷骰，权重由 `--mix LAIKA MPC FROZEN` 给。按环境编号分配是错的——
策略能分辨自己在哪条支线。

| 对手 | 如何驱动 |
|---|---|
| Laika | `Game::with_ai(seed, 2, &[1])`，引擎在 `tank_update` 内部驱动 |
| MPC | 每槽一个 `KillFieldAgent::new(1, seed)`，`before_step` 里 `drive`。**必须设 `OppModel::L1`** |
| Frozen | 权重在训练器里，环境发布 tank 1 视角的观测，训练器过一遍冻结网络再把动作喂回 |

`OppModel` 那条：默认的 `L2` 会在前视里推演真正的 Laika 脚本，只有当对手确实是
Laika 时才成立。面对学习策略，诚实的设定是 L1（冻结对手当前按键）。

冻结档用**采样**不用 argmax——确定性的池对手是一段可以背诵的脚本。

帧内顺序有一个已知的不对称：`step()` 按 tank 序号迭代，tank 0 先动，Laika 的控制器
随后运行并**看到我们本帧移动后的新位姿**；而 MPC 在 `step()` 之前决策，看到的是旧
位姿。也就是 Laika 领先我们半帧、MPC 落后半帧。这个不对称偏向 Laika、亏待 MPC。
